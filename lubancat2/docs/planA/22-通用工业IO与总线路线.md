# 22 · 通用工业 I/O 与总线路线（PLC 级产品演进）

> 状态：**方案评审稿（2026-10-01）** ｜ 前置：`20`（Modbus 从站产品化 P1~P3 已部署）、`21`（Modbus 主站 P4，M-P1/M-P2 完成）
> 一句话：把现有「Modbus 主/从」升级为**统一信号模型 + 可插拔协议后端**，按路线 A→B→C 逐步做成
> PLC 级产品：先补信号变换/强制/跨连接，再铺协议（CANopen/EtherNet-IP/PROFINET）与 OPC UA，
> 最后按市场决定是否引入 IEC 61131-3 运行时与安全认证子系统。

---

## 1. 定位与目标

现状：控制器已具备 **Modbus 从站**（固件 502，组态/命名/热加载）与 **Modbus 主站**（设备+点位），
以及 **EtherCAT 主站**（IgH）与运动内核。与 ABB 机器人 I/O 系统对照，缺的是「通用性」：
信号变换、跨协议互联、工程组态导入、强制/诊断、多协议主/从、PLC 语言与安全。

| # | 目标 | 说明 |
|---|------|------|
| G1 | **统一信号模型** | 设备→点位→**信号**（名称/类型/单位/量程/变换/事件/诊断/保持）；协议无关，是产品的核心资产 |
| G2 | **协议后端可插拔** | Modbus/EtherCAT/CANopen/EtherNet-IP/PROFINET/OPC UA 各自实现统一后端接口；增协议=加插件 |
| G3 | **工程化组态** | 设备描述导入（EDS/GSDML/ESI）生成点位草稿；模板/批量/校验；在线监视与**强制** |
| G4 | **跨连接（cross connection）** | 信号↔信号、信号↔4x、跨协议互联，不写脚本 |
| G5 | **PLC 级运行时（择机）** | IEC 61131-3（买 CODESYS 或 OpenPLC/Beremiz）与 Lua 并存，按市场决定 |
| G6 | **合规与安全** | 一致性认证路径（ODVA/PI/ETG）与安全子系统（硬件为主） |

**不做（边界）**：不追"协议数量"本身；不做安全认证软件栈；不迁移本工程既有业务（称重/泵仍按现状，后续可选重构）。

## 2. 目标架构

```
[工程工具 / 插件 UI]  →  [信号注册表 Signal Registry]  →  [I/O 后端插件]
 设备描述导入(EDS/ESI)     设备→点位→信号（协议无关）        Modbus（已有，第一个后端）
 在线监视 / 强制            类型/单位/量程/scale/offset      EtherCAT（已有 IgH 主站）
 模板/批量/审计             事件/滤波/保持/质量码             CANopen（CANopenNode）
 跨连接编辑器               互联规则（cross connection）       EtherNet-IP（OpENer，适配器）
                            ↑ 脚本访问：MB_READ("设备.点位")   PROFINET（p-net 商用，适配器）
                                                              OPC UA（open62541，服务器）
```

**后端接口（草案）**：`scan()` / `load(cfg)` / `read_point()` / `write_point()` / `status()` /
`subscribe(change)` / `diagnostics()`。现有 `ModbusMaster` 抽出接口即第一个实现，
`ModbusServer` 作为"从站侧后端"并列；EtherCAT 保持 RT 核心内直通（不经过非 RT 后端框架）。

**关键原则**：
1. 信号模型先于协议数量——模型不稳，接十个协议也是返工；
2. RT 核（1ms）只保留 EtherCAT 与运动；所有新协议跑非 RT 线程；
3. 一切组态热加载（沿用 D12/D13 模式）+ 原子替换 + 失败不碰运行实例；
4. 降级不伪装（沿用项目铁律）：能力不上报就不显示，不返回"成功但零效果"。

## 3. 协议选型调研（2026-10-01 核实）

| 协议 | 可行方案 | 许可 / 成本 | 角色 | 结论与备注 |
|------|----------|-------------|------|------------|
| Modbus TCP | 自研固件（已有） | — | 主 + 从 | 保持；作为后端框架的首个实现 |
| Modbus RTU | **libmodbus** | LGPL-2.1 | 主 + 从 | 本机无 RS485/CAN → 走透传网关（现状）或加 USB-485 |
| EtherCAT | **IgH EtherLab**（已用）/ SOEM（RTLabs，2.1k★） | GPLv2 类 | 主站 | 主站已具备；重点转为**标准 IO 端子接入 + PDO→信号映射** |
| CANopen | **CANopenNode**（Apache-2.0，2k★） | 宽松 | 主/从全功能 | NMT/PDO/SDO/**CiA309 网关**/**SRDO 安全**（CiA304），已过一致性测试；需 CAN 硬件 |
| EtherNet/IP | **OpENer**（863★，ODVA 对象集，适配器侧，支持 PREEMPT_RT） | 宽松（用前核对 license.txt） | **适配器（从）** | 做"被 PLC 访问"可行；scanner（主）侧开源薄弱 → 商业栈或通信模块 |
| PROFINET | **p-net**（RTLabs） | ⚠️ **开源仅评估版；产品使用须购买商业许可** | 适配器（从） | 仓库明示"evaluation only"；控制器（主）侧基本商业 |
| OPC UA | **open62541**（3.2k★） | **MPLv2**（可静态链接闭源） | 服务器 + 客户端 | 官方示例服务器已过 OPC 基金会认证（Standard Server 2017）；含 PubSub/TSN；上接 IT/SCADA/MES 首选 |
| MQTT / Sparkplug B | mosquitto + paho / Sparkplug 规范 | 宽松 | 发布 | 轻量上云（后续可选） |
| PLC 运行时 | **CODESYS**（商业，ARM Linux 成熟）；**OpenPLC**（GPLv3）；**Beremiz**（GPLv2，IEC 61131-3 IDE）；**4diac FORTE**（EPL，IEC 61499） | 混合 | — | 语言生态决定买 CODESYS 还是用开源；后者采纳前需复核版本/许可 |
| 安全总线 | 无成熟可认证开源栈（PROFIsafe/CIP Safety 商业） | — | — | **安全必须硬件化**（安全继电器/安全 PLC/认证模块） |

> 来源：各项目官方仓库（p-net/OpENer/SOEM/CANopenNode/open62541）当日核对；OpenPLC/Beremiz 未完成线上复核，标注"待复核"。

## 4. 三条路线（按野心递进）

### 路线 A · 务实增强（1~3 个月，推荐先行）
- 信号模型扩展（scale/offset/unit/min/max/deadband/事件）落地到现有 D13 点位 schema；
- 在线**强制/仿真**与监视；
- cross connection 最小集（信号↔信号、信号↔写点）；
- EtherCAT 标准 IO 端子接入（PDO→信号）；
- OPC UA 服务器 v1（只读浏览/订阅 + 按权限写）。
- 多协议按订单用商业通信模块（Anybus/Hilscher）补。

### 路线 B · 平台化（6~12 个月）
- 后端接口 + 插件化：libmodbus(RTU)、CANopenNode、OpENer；p-net（商用）视订单；
- 设备描述导入（EDS/ESI/GSDML）与设备模板库；
- 每信号质量码/时间戳、统计、事件→日志/报警；
- 跨协议 cross connection 编辑器。

### 路线 C · PLC 级正统（12 个月+）
- IEC 61131-3 运行时（CODESYS 或开源）与 Lua 并存；
- 协议一致性认证（ODVA/PI/ETG 会员与测试费）；
- 安全子系统：硬接线安全回路或认证安全模块 + 商业安全协议栈。

## 5. 分期路线图与验收（第一阶段展开）

| 里程碑 | 内容 | 交付物 | 验收 |
|--------|------|--------|------|
| **M-A1** 信号变换 | D13 点位扩展 `scale/offset/unit/min/max/deadband`；读点正变换、写点逆变换；插件列 + 校验 + 热加载 | schema + 固件 + 插件 | ctest 新用例；真机：raw→显示值换算正确，越限标记质量位 |

| **M-A3** 跨连接最小集 | 规则表 `{from, to, filter, min_interval}`；源信号变化→更新目标（4x/变量/写点） | schema + 引擎 + 插件页 | 真机：设备 A 读点→4x；设备 A→设备 B 写点 |
| **M-A4** OPC UA v1 | open62541 服务器：信号树、浏览/订阅、按 access 写 | 固件集成 + 文档 | UaExpert 浏览/订阅；写被权限拦截（降级不伪装） |

IEC 61131-3 评估（M-C1）→ 安全与认证（M-C2）。

## 6. 信号 schema 草案（与现有 D13 兼容）

```json
{
  "name": "输出频率",
  "dir": "read", "fc": 3, "addr": 9, "count": 1, "type": "u16",
  "map": { "kind": "reg", "addr": "4x601" },
  "scale": 0.1, "offset": 0, "unit": "Hz",
  "min": 0, "max": 50, "deadband": 0.05,
  "events": { "on_change": true, "min_interval_ms": 100 }
}
```
- 读：`值 = raw × scale + offset`；写：`raw = (值 − offset) ÷ scale`（scale=0 视为非法）。
- `min/max` 越限仅置质量位/告警，不拦写（是否拦截由 `clamp` 可选项决定，v2 再议）。
- 全部字段可热加载；旧配置缺省 `scale=1, offset=0`，**向后兼容**。

**cross connection 草案**：
```json
{ "rules": [ { "from": "变频器1.输出频率", "to": "4x601", "filter_ms": 50, "min_interval_ms": 100 } ] }
```

## 7. 风险与合规

| 风险 | 说明 | 对策 |
|------|------|------|
| 许可 | IgH/SOEM 为 GPL 系；闭源产品需法务评估隔离方式 | 保持独立进程/内核模块边界；必要时评估商业 EtherCAT 主站 |
| 认证 | EtherNet-IP/PROFINET 商标 + 一致性认证（会员/测试费） | 按订单启动；先用现成模块过认证 |
| 实时性 | RK3568 有限，协议越多越挤 | RT 核只留 EtherCAT/运动；新协议非 RT；必要时加通信模块分担 |
| 硬件扩展 | 无 CAN/RS485 本口 | USB-CAN/USB-485、远端 IO 模块或自定义板卡 |
| 安全 | 软件无法替代认证安全回路 | 安全保持硬接线；上安全总线走商业认证栈 |
| 工程效率 | 无描述导入时点位手填易错 | M-A6 起逐步支持导入；先用模板+校验兜底 |

## 8. 待决问题（评审）

1. **IEC 61131-3 语言生态**是否为目标客户硬需求（决定 CODESYS 采购 vs 开源运行时）？
2. **目标市场与认证**：CE/UL？是否需要 ODVA/PI 认证，或先用通信模块规避？
3. **闭源边界与 GPL**：EtherCAT 主站（IgH）长期方案的法务结论。
4. **硬件扩展形态**：CAN/RS485 走 USB 适配器还是远端 IO 模块/自定义板卡？
5. **安全策略**：保持纯硬接线，还是规划认证安全模块接口？
