# 20 · Modbus 配置与固件封装设计（产品化）

> 状态：**P1+P2+P3 完成——固件 502 已正式接管 502（2026-10-01，913224 B）**：脚本经 `kx_mbsync` 与固件库存按区同步（脏字回推）；`config/modbus.enable` 放行；Lua 502 线上处理与 kx_regmap 用户区退役；闭环真机验证通过 ｜ 前置：`05`、`13`、`18`、`19`
> 目标读者：控制器固件开发 / 插件开发 / 现场集成
>
> 一句话：把 Modbus 做成**控制器固件内建能力（C++）**——客户拿到控制器、**不写任何协议代码**，
> 在插件里组态「变量名 ↔ 寄存器地址 ↔ 数据类型 ↔ 读写方向」，脚本里**按名字**读写；
> 触摸屏/机器人仍按**地址**访问。对齐 ABB（信号映射）/珞石（总线设备+按名读写）/正运动（固件内建 502）的使用习惯。

## 1. 设计目标与不变量

**目标（产品化）**

| # | 目标 | 说明 |
|---|------|------|
| G1 | **固件内建、零脚本依赖** | 客户脚本为空也有完整 502 从站；Modbus 引擎不在任何 `.lua/.bas` 中 |
| G2 | **插件组态** | 「Modbus 从站」页（原「Modbus 配置」）：变量名/地址/类型/读·写·读写/掉电保持/默认值/说明；保存即热加载，免重启 |
| G3 | **脚本按名使用** | `MB_READ("温度设定")` / `MB_WRITE("温度设定", 42)` / `MB_LIST()`（BASIC 与 Lua 同名命令，语言无关） |
| G4 | **地址访问并行可用** | 触摸屏/机器人按 4x 地址读写，语义与现在完全一致（本项目 `05/18/19` 不变量不动） |
| G5 | **通用性** | 不绑定称重/泵/机器人/触摸屏——这些是"本工程脚本"的事；固件只提供通用寄存器与组态 |

**不变量（继续遵守）**：4321 ASCII 字面量、本项目 502 地址/字序/状态位（`05/18/19`）、
`eth1` 业务网配置、`1 unit = 1 mm`。改造期**旧 ZMC 控制器不拆除**，可随时回退。

## 2. 调研对照（为何选"组态 + 按名使用"）

| 平台 | 用户配置形态 | 程序怎么用 | 启示 |
|------|--------------|------------|------|
| **正运动 ZMC** | 从站**固件内建 502**（无需配置/OPEN）；寄存器在程序里用 `MODBUS_REG(n)/MODBUS_IEEE(n)` 直接映射 | 直接读写信内寄存器；屏/PLC 轮询同地址 | 固件内建是底线；映射要"触手可及" |
| **西门子 S7** | **组态连接 + 指令实例**（`MB_CLIENT/MB_SERVER`；`MB_DATA_PTR` 指向 DB） | 周期调用指令，数据落在 DB 偏移 | 连接与点表显式；但点表要"程序里维护"（用户负担） |
| **ABB 机器人** | **信号映射组态**：Unit→Signal，信号绑定总线地址与类型 | RAPID 直接用**信号名**（SetDO/SetGO/…） | **地址→命名**是最高效的用户面 |
| **珞石 xCore** | **总线设备表格**：模式/从站 ID/IP/端口/**寄存器起始+个数**；每总线独立开关 | 生成**命名寄存器**，`ReadRegByName(...)`/`WriteRegByName(...)` 按名读写；IO 走 FIELDBUS 信号 | 与我们的目标形态最接近（表格 + 按名） |

**结论**：固件内建（ZMC）+ 表格组态（xCore）+ 按名使用（ABB/xCore）三合一。
另注：xCore 主站侧**仅支持单从站**且**不支持 0x04**——我们固件引擎按更完整的能力做（多客户端/FC 全支持）。

## 3. 总体架构

```
┌──────────────────────────── 固件（C++，随控制器出厂） ────────────────────────────┐
│  ModbusServer（独立服务线程，非 RT）                                                │
│   ├─ TCP 502 监听（多客户端；与 debug server / PortManager 并列的进程级服务）        │
│   ├─ 协议引擎：FC 01/02/03/04/05/06/0F/10（异常码 0x01/0x02/0x03）                   │
│   ├─ 寄存器库存：4x 全空间 u16（分区分语义由配置叠加）                               │
│   ├─ 组态映射表（config/modbus.json）：name↔addr↔type↔access↔persist↔default↔desc   │
│   ├─ 命名访问 + 类型编解码（u16/i16/u32/f32、字序可选、32 位占 2 寄存器）            │
│   ├─ 持久化：persist 条目 → NvramStore（写即落盘；上电恢复）                          │
│   └─ 热加载：配置变更原子替换；失败保留旧表并日志（不半生效）                           │
├────────────────────────────── 命令面（语言无关） ────────────────────────────────┤
│  MB_READ(name) / MB_WRITE(name, v) / MB_LIST()   ← 注册进 BASIC 与 Lua 两个引擎      │
│  兼容保留：MODBUS_REG/MODBUS_IEEE（按地址；现有工程与客户习惯均不变）                 │
├────────────────────────────── 调试协议（插件用） ─────────────────────────────────┤
│  D12：mbreg.get → {file, exists, text}；mbreg.set {text} → 原子写 + 即时热加载        │
│  （v0.9/v0.10 的 D11/.mbmap 为过渡形态；见 §8 迁移）                                 │
├────────────────────────────── 插件（VSCodium） ──────────────────────────────────┤
│  「工具 → Modbus 从站」：组态表格（增删改/校验/保存）+ 服务信息（端口/站号/客户端）    │
└───────────────────────────────────────────────────────────────────────────────────┘
本工程脚本（demo.lua）│ 机器人桥接 / 称重 / 泵 / 校准：经 MODBUS_REG 等命令读写寄存器（地址语义不变）
```

**职责边界**：固件只做"通用 Modbus 寄存器设施"（协议、组态、类型、权限、持久化、按名访问）；
**业务语义**（哪个地址代表机器人心跳、泵状态码……）仍归**本工程脚本**，不进入固件。

## 4. 配置模型

**文件**：`/userdata/kine-x/config/modbus.json`（产品配置目录，持久；与 `app.conf` 同级不同文件）
**兼容**：迁移期固件同时识别旧脚本目录 `.mbmap`（只读合并，见 §8），P3 后废弃。

```json
{
  "version": 1,
  "station": 1,
  "registers": [
    { "name": "温度设定", "addr": "4x300", "type": "f32", "access": "rw",
      "persist": true, "default": 25.0, "desc": "烘箱温度设定值" },
    { "name": "运行状态", "addr": "4x310", "type": "u16", "access": "r",
      "persist": false, "desc": "0=停止 1=运行 2=故障" },
    { "name": "启动命令", "addr": "4x311", "type": "u16", "access": "w",
      "persist": false, "desc": "写 1 启动（主站）" }
  ]
}
```

| 字段 | 取值 | 说明 |
|------|------|------|
| `name` | 字符串，建议 `[A-Za-z0-9_\u4e00-\u9fa5]{1,32}`，表内唯一 | 脚本 `MB_READ/WRITE` 的键；`MB_LIST()` 返回 |
| `addr` | `4xN`（N=0..65535 内、且不与 32 位条目跨占） | 起始地址；32 位类型占 `N`、`N+1` |
| `type` | `u16`/`i16`/`u32`/`f32`/`f32hi` | `u32/f32`=低字在前（屏约定）；`f32hi`=高字在前（泵约定）；各占 2 寄存器 |
| `access` | `r` / `w` / `rw`（**对主站**的方向） | `r`：主站只读（脚本写值，如状态）；`w`：主站只写（脚本读值，如命令）；`rw`：双向 |
| `persist` | true/false | true → 任何写入（主站或脚本）即落盘，上电恢复（NvramStore） |
| `default` | 数字（可选） | 首次上电（无持久化记录）的初始值（按类型解码） |
| `desc` | 字符串（可选） | 说明（插件展示） |

**地址空间策略（待评审，推荐 A）**
- **A（推荐，ZMC 兼容）**：4x 全空间 = 普通 u16 寄存器（脚本 `MODBUS_REG` 可读写；主站可读写）；
  组态条目在其地址上**叠加**类型/权限/持久化/命名语义。未组态地址行为=现 ZMC（读 0、可写）。
- B（严格）：未组态地址 → 异常 0x02（xCore 风格）。**本项目有大量固定区（0~255/1000~1199），选 A 最平滑**。

**校验规则**：地址冲突（含 32 位跨占）拒绝；名称唯一；类型/权限枚举；`default` 按类型范围；
单表条目 ≤ 1024；失败**整表不生效**并给出首个错误（`planA/13` 风格：明确报错不静默）。

## 5. 命令与调试协议

### 5.1 脚本命令（语言无关，两个引擎同名）
| 命令 | 语义 |
|------|------|
| `MB_READ(name)` | 按名读值（`r`/`rw` 合法；`w` 条目亦可读=命令当前值？→ **允许读**，便于脚本处理；只对**主站**限制方向） |
| `MB_WRITE(name, v)` | 按名写值（`w`/`rw` 合法；对 `r` 条目 → 脚本侧**允许**（脚本是"数据源方"），主站侧才拒绝 → 语义见下注 |
| `MB_LIST()` | 返回 `{name, addr, type, access}` 列表（脚本自省/提示用） |

> **方向语义注解**（与 ABB 的 di/do 同思路）：`access` 描述**主站权限**。
> `r` 条目 = 脚本产出/主站消费（脚本可写、主站只读）；`w` 条目 = 主站产出/脚本消费（主站可写、脚本只读语义上"读即可"）。
> 脚本侧对 `MB_WRITE` 一律允许（它是"数据源"），主站侧才按 `access` 拒绝（写只读 → 异常 0x02）。

### 5.2 调试协议 D12（`planA/13` 增补）
| 方法 | 参数/返回 | 说明 |
|------|-----------|------|
| `mbreg.get` | → `{file, exists, text, applied, count}` | 读组态文本 + 生效状态 |
| `mbreg.set` | `{text}` → `{bytes, applied, count}` | 原子写 + **即时热加载**；校验失败 → `BAD_PARAM` + 首错 |

`caps` 增 **`d12`**；插件缺 `d12` 置灰（降级不伪装）。

### 5.3 兼容
- `MODBUS_REG/MODBUS_IEEE`（按地址）保留，映射到同一库存 → 本工程与老客户脚本零改动。
- D11（`.mbmap` / 用户寄存器 4x300~999）迁移后废弃（见 §8）。

## 6. 运行时行为

| 主题 | 约定 |
|------|------|
| 502 服务 | 多客户端（≥4）；FC 01/02/03/04/05/06/0F/10；异常码：非法功能 0x01 / 非法地址或只读写 0x02 / 非法数据 0x03 |
| 客户端上限/保活 | 沿用现有（4 客户端 + SO_KEEPALIVE ~25s 判死） |
| 热加载 | 文件哈希轮询（≤1s）或 `mbreg.set` 触发；解析/校验失败**保留旧表**并打印首个错误 |
| 持久化 | `persist` 条目写入即 NVSET（含主站写入路径）；上电顺序 = 库存初始化 → 恢复持久值 → 网络就绪 |
| 线程模型 | 服务线程独立（非 RT）；库存读写加锁或原子快照；与 RT 1ms 循环**零耦合** |
| 默认值 | 无持久化记录且配置有 `default` → 应用 default；否则 0 |
| 日志 | 组态生效：`[mbreg] 生效 N 条（…）`；失败：`[mbreg] 配置未生效：<首错>`；主站写只读：限频日志 |

### 8.1 脚本按名访问层（v0.12.2，2026-10-01 落地）

本工程 Lua 脚本（`EtherCAT_SocketServer.lua` + `kx_*.lua`）**调用点保持 `reg_get/reg_set/...` 形态不变**，
内部实现已切换为**按名访问**（兼容层，零调用点改动）：

- **装载**：启动时（在 `nvram_restore` **之前**）与运行期每 5s，`kx_base.lua` 的 `mbnames_refresh()` 用 `MB_LIST()` 装载
  「地址 → 变量名 + 类型字数」映射（组态热更新后自动跟随）。
- **单字条目**：`reg_get(a)` → `MB_READ(名)`；`reg_set(a,v)` → `MB_WRITE(名,v)`（直达固件库存，persist 由固件处理，不产生脏字）。
- **2 字条目**（f32/u32/f32hi）：`reg_get_f/reg_set_f(a)` → `MB_READ/MB_WRITE(名)` 成对解码/编码；
  字级对 2 字起始地址的读写仍走本地字缓存（不改变原语义）。
- **未组态地址回退**：旧本地缓存 + `kx_mbsync` 按区同步（pull 非脏 / push 仅脏段）——安全网，行为与 P3b 相同。
- **收益**：读到的即固件库存（无 pull 周期延迟）、写直达（无 push 延迟）、与主站/屏写入天然一致；组态改名 5s 内自动生效。
- **覆盖**（本工程常量访问 79 地址）：**69 条按名**；回退 10 个 = 4x65（64 浮点的高位字）/ 4x143~150（镜像区未组态行）/ 4x1013（机器人区未组态行）。

自测：`port_script_selftest` 新增 3h 组 6 项（单字按名直达、直读固件无需 pull、未组态回退不破坏、浮点成对写/读、外部改字即时可见）；
`ctest` 19/19 全绿。

## 10. 开放问题（已按推荐定案，2026-10-01）

1. **地址空间策略 = A**：4x 全空间 permissive（未组态=普通 u16，ZMC 兼容）；严格模式留作未来配置项。

3. **名称允许中文（UTF-8）**；脚本内建议 ASCII 名（跨语言填写更稳）。
4. **D11 废弃节奏**：P3 收口后保留一个版本（弃用提示），随后移除。
5. **主站侧（P4）单独设计**（本文件预留；不与从站同表混排）。
6. **出厂 = 空表**（`modbus.json` 缺失即以空表运行；示例见本文档/插件提示，不预置条目避免误用地址）。
