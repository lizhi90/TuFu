### 1.2 关键发现

| 问题 | 实测结论 |
|------|----------|
| 双网口怎么分？ | `eth1` 已带业务 IP；`eth0` 空闲 → 定 `eth0` 做 EtherCAT 专用 |

| sudo 免密吗？ | 可用（`sudo -n true` 通过）→ 脚本可全自动 |
| 外网通吗？ | gitlab/github/镜像站可达，DNS 正常 → 板上能自己下依赖 |

> 结论：板端具备「本地编译 IgH + 本地编译自检程序」的全部条件，无需交叉编译。这一判断在 §3.1 进一步论证。

### 2.2 实测抖动（cyclictest `-S -p90 -i1000 -D 60`，µs）

| 场景 | Min | Avg | **Max** |
|------|-----|-----|---------|
| 未调优基线 | 7 | ~41 | 915 / 887 / 1035 / 1084 |
| 调优后·空闲 | 6 | 8~19 | 679 / 445 / 578 / 593 |
| 调优后·加压 | 6 | 8~19 | 538 / 559 / 598 / 537 |
| **持久化生效·空闲** | 6 | 9 | **412 / 506 / 539** |
| **持久化生效·加压** | 6 | 20/18/18 | **427 / 348 / 431** |

**结论**：Max ~1.1ms → ~0.53ms，Avg ~41µs → ~9µs；加压不劣化（瓶颈在非 RT 内核临界区，不在业务负载）。
对「单轴 PP 定位 + 点动 + 1ms 周期」满足。

## 3. IgH EtherCAT Master 编译安装

### 3.1 为什么不交叉编译（PC 编译好再传板）

用户最初想法是「PC 上编译好传板」。实测论证**不可行/不划算**，三证据：

1. **PC 没有匹配的内核源码/头文件** —— 板端是 Rockchip 定制 `6.1.99-rk356x`，PC 上不存在可直接用的构建树。
2. **板端内核构建工具是 aarch64 静态 ELF** —— `scripts/mod/modpost`、`scripts/basic/fixdep` 是 **aarch64 ELF static**，在 x86 PC 上直接 `Exec format error`。
3. **代价高** —— 要把 **~1.5G 内核源码 + ~108M headers** 回传到 PC，只为编两个 `.ko`。

> 最终方案：**PC 只做「取源码 + 传输」，编译全部在板上**（板上 `Module.symvers` 与运行内核天然一致）。

### 3.2 版本选择

选 **IgH 1.6.13**：`devices/` 目录已含 `-6.1-` 内核变体，对 `6.1.x` 适配到位。
下载仓库用 **gitlab**（`gitlab.com/etherlab.org/ethercat`）；github 上的 fork 拉取会报 `could not read Username`（要求鉴权），不要用。

### 3.3 操作流水

```bash
# 1) 本机：把 et.tgz 传板解压到 /opt/kine-x/ethercat
./deploy/bg.sh /tmp/igh_push.log ./deploy/push-igh.sh /tmp/et.tgz

# 2) 板端：装编译依赖（build-essential/autoconf/libtool/...）
./deploy/run_bg.sh deploy/15-igh-deps.sh /tmp/igh_deps.log

# 3) 板端：bootstrap + configure + make + 安装
./deploy/run_bg.sh deploy/16-igh-build.sh /tmp/igh_build.log

# 4) 板端：写主站配置并启动
./deploy/run_bg.sh deploy/17-config-master.sh /tmp/igh_cfg.log
```

`16-igh-build.sh` 的 **configure 开关**（只留必要项）：

```
--prefix=/usr/local
--with-linux-dir=/lib/modules/$(uname -r)/build
--enable-generic                      # 只编 generic 驱动（板载网卡走 generic 接管）
--enable-tool --enable-userlib        # ethercat CLI + libethercat
--disable-eoe
--disable-8139too --disable-e100 --disable-e1000 --disable-e1000e
--disable-genet --disable-macb --disable-igb --disable-igc
--disable-r8169 --disable-stmmac-pci --disable-dwmac-intel
--disable-ccat --disable-rtdm
--disable-initd
--with-systemdsystemunitdir=/lib/systemd/system
```

> 说明：`--disable-initd` + `--with-systemdsystemunitdir=/lib/systemd/system` 是为了统一走 systemd；
> 其余原生网卡驱动全关，避免与 `st_gmac` 抢 `eth0`。

### 3.4 产物与 M1 实测

产物：

- `master/ec_master.ko` → `/lib/modules/$(uname -r)/ethercat/`
- `devices/ec_generic.ko` → 同上
- `/usr/local/bin/ethercat`（CLI）、`/usr/local/lib/libethercat.so*`（用户态库）

启动结果：

- `ec_master` + `ec_generic` 加载成功，`/dev/EtherCAT0` 就绪
- `ethercat master` 显示 `Main: 8e:56:ce:3f:af:2b (attached)` → generic 驱动已绑定 `eth0`

### 3.5 配置要点（`17-config-master.sh`）

- **`MASTER0_DEVICE` 可以写网口名**（如 `eth0`），IgH 的 `parse_mac_address()` 会自动解析成 MAC；
  也可以直接写永久 MAC `8e:56:ce:3f:af:2b`（更稳，本例采用）。
- **`DEVICE_MODULES="generic"`**：明确用 generic 驱动。
- **配置路径定位**：`--prefix=/usr/local` 时 `ethercatctl` 读的是 **`/usr/local/etc/ethercat.conf`**，不是 `/etc/ethercat.conf`。
  脚本直接从 `ethercatctl` 里 grep 出真实路径，并同份写一份到 `/etc/ethercat.conf` 便于查阅。
- 启动前先 `systemctl stop ethercat` + `rmmod ec_generic ec_master`，规避 §5.4 的坑③。

## 4. `ecat_probe` 上板验证

### 4.1 板上没有 cmake → g++ 直编

`ecat_probe` 依赖极简（`ethercat_master.cpp` + `rt_util.h` + `ecrt.h`），**不必为一个自检工具去装 cmake**。
用 `deploy/19-build-probe.sh` 直接 `g++`：

```bash
g++ -std=c++17 -O2 -Wall -pthread \
  -I/usr/local/include -Isrc \
  tools/ecat_probe.cpp src/motion/ethercat_master.cpp \
  -o ecat_probe \
  -L/usr/local/lib -lethercat -lpthread -lrt
```

### 4.3 实测结果

- `ecat_probe` 运行输出：`Requesting master 0... Successfully requested master 0.`
  → **ecrt 用户态接口打通**（可申请主站、可运行周期）。

## 5. 经验与踩坑汇总

### 5.1 远程操作（PC ↔ 板）

- **免交互 SSH**：本机没有 `sshpass`，用 `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force` + `DISPLAY=:0` 提供密码。
  `ssh_run.sh` 已封装，并带重试（sshd 可能限流）。
- **长任务别走前台**：`scp`/`configure`/`make` 可能被上层执行器直接跳过（"可能耗时"）。
  用 `bg.sh`（本机后台）或 `run_bg.sh`（板上后台）+ 日志文件（`tail -f` 看进度）。
- **`bg.sh` ≠ `run_bg.sh`**（详见 §0.2）：一个跑本机、一个跑板上。**最容易犯的错**是把本机脚本交给 `run_bg.sh`，
  表现为远端找不到文件、一直"打包失败"。
- **引号转义是雷区**：把带引号的复杂命令塞进 `ssh "...\"...\""` 容易 `bash: unexpected EOF`。
  正确做法：**写成独立脚本**（如 `20-run-probe.sh`）再送过去，不要在远端拼一行。
- **重试链会重复副作用**：`ssh_run.sh` 失败重试会把整个 `configure+make` 重跑，出现两个 `configure` 进程。
  对策：脚本内**幂等**（已存在 `Makefile`/`config.status` 就跳过 configure，`FORCE_CONFIGURE=1` 强制重配），
  重试前先 `pkill` 清掉残留进程。

### 5.2 系统与启动

1. **`extlinux.conf` 改了没用** → 真正入口是 `/boot/uEnv/uEnv.txt`（`boot.scr` 用 `env import -t` 追加 `cmdline=`）。
2. **内核没开 `NO_HZ_FULL`** → `nohz_full=3` 是无效参数，别加（只有 `CPU_ISOLATION`/`RCU_NOCB_CPU` + `NO_HZ_IDLE`）。
3. **`eth0` down 时看不到它的 IRQ** → 必须在启动主程序时先 `ip link set eth0 up` 再绑亲和（`13-pin-irq.sh`）。
4. **`sched_rt_runtime_us` 默认 95%** → 不设 `-1`，RT 线程会被周期性节流，表现为"偶发大延迟"。
5. **一键 `apply` 的批量 IRQ 迁移会误伤 EtherCAT 口** → 迁移循环必须排除 EtherCAT 网口的 IRQ。

### 5.3 内存/缓存依赖（libethercat 找不到）

- `libethercat.so.1` 装在 `/usr/local/lib`，**不刷新动态库缓存**会出现：
  `error while loading shared libraries: libethercat.so.1: cannot open shared object file`。
- 修复：`sudo ldconfig`。已固化进 `16-igh-build.sh` 的安装步骤，避免每次手工补。
- 症状补充：`ecat_probe --help` 之前 `ldd` 也报 `not found` → 同一个根因，`ldconfig` 一并解决。

### 5.4 IgH 三个真实坑（按重要性）

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| ① | `make` 成功但没有 `.ko` | IgH 内核模块**不在 `all` 目标**里（`master/`、`devices/` 的 `all` 为空） | `make all` 之后**显式 `make modules`** |
| ② | 程序报 `libethercat.so.1 not found` | `/usr/local/lib` 未进 ld 缓存 | `sudo ldconfig` |
| ③ | `/dev/EtherCAT0` 不生成、`ethercat master` 报 `No such file or directory`（但 service 显示 success） | 编译脚本"试加载"了**无参** `ec_master`；之后 `ethercatctl` 用 `main_devices=<MAC>` 再 `modprobe` 被当成 no-op（模块已加载），主站没被创建 | `16` 试加载后 `rmmod` 卸载；`17` 启动前 `systemctl stop` + `rmmod` 再 `start` |
| ④ | 服务以非 root 用户运行时报 `/dev/EtherCAT0: Permission denied`，启动即退出，5000 不监听 | 设备节点默认 `crw------- root root`，仅 root 可访问；`kine-x` 以 `cat` 用户运行 | udev 规则持久化 + 立即授权：`echo 'KERNEL=="EtherCAT[0-9]*", MODE="0660", GROUP="realtime"' | sudo tee /etc/udev/rules.d/99-kine-x-ethercat.rules`；`sudo chgrp realtime /dev/EtherCAT0 && sudo chmod 660 /dev/EtherCAT0`；`sudo systemctl restart kine-x` |

> 坑③最隐蔽：服务"成功"但功能不通。**判据**：`ls /dev/EtherCAT*` 必须存在；`ethercat master` 必须显示 MAC + `(attached)`。

### 5.5 排查手法（可复用）

```bash
# 主站看门狗
ls -l /dev/EtherCAT*                  # 没有 → 主站没建起来
lsmod | grep -E '^ec_'                # 看模块是否加载、以及是否带参数
dmesg | grep -iE 'ethercat|ec_master|ec_generic' | tail -20
sudo ethercat master                  # Main: <MAC> (attached) 才算 OK
sudo ethercat slaves -v               # 从站与 AL 状态

# 物理链路
ethtool eth0 | grep -E 'Speed|Link detected'
cat /sys/class/net/eth0/addr_assign_type   # 0=永久MAC（可作 MASTER0_DEVICE）
```

**顺序**：物理链路（Link）→ 主站设备（`/dev/EtherCAT0`）→ 模块绑定（MAC attached）→ 用户态（ecrt）→ 从站（slaves）。

## 7. M1 排障实录：AL `0x001E` → 进 OP

现象：SV630 接线正常、`ethercat slaves` 能看到 `PREOP`，但三档显式 PDO 映射全部停在
`PREOP + ERROR`，AL 码 `0x001E`（Invalid input configuration），过程数据全 0。

### 7.1 排查链（每一步都用脚本留证据）

| 步骤 | 脚本 | 结论 |
|------|------|------|
| 抓主站写下的 SM 页 | `30-safeop-trace.sh` | `SM2 Size 12 / SM3 Size 28` —— **用的是 SII 默认长度，不是我们的 7/6** |
| 抓应用层配置 API | `31-config-api-trace.sh` | `ecrt_slave_config_pdo_mapping_add 0x1600:6040/607A/6060`、`0x1a00:6041/6064` **全部成功** |
| 读 IgH 源码 | `/tmp/ethercat-1.6.13/master/slave_config.c` | `ec_slave_config_attach()` 要求 **vendor/product 与 SII 精确相等**；不匹配则 `slave->config==NULL` |
| 推结论 | `ec_fsm_slave_config_enter_pdo_sync()` | SM 长度 = `slave->config ? pdo_list_total_size() : sync->default_length` → 走默认分支 |

### 7.2 根因

`config/app.conf` 里**没有** `ECAT_VENDOR`/`ECAT_PRODUCT`，代码默认值又是 `0/0`。
IgH 里 **`0` 不是通配符**（除非编译时开 `EC_IDENT_WILDCARDS`），
于是 `attach` 失败，我们精心写的 PDO 映射被**静默忽略**，回落到 SII 的 12/28，
从站自然报 `0x001E`。

> 这个 bug 最坑的地方：**应用层调用全部返回成功**，只有内核 SM 页能看出真相。

### 7.3 修复

| 文件 | 改动 |
|------|------|
| `src/common/config.h` | `vendor_id=0x00100000`、`product_code=0x000c0112`（默认即 SV630 真值） |
| `src/motion/ethercat_master.h` | 同上，并更正 "0 = 不校验" 的错误注释 |
| `tools/ecat_probe.cpp` | `--vid/--pid` 默认改为 SV630 真值 |
| `config/app.conf` | 新增 `ECAT_VENDOR` / `ECAT_PRODUCT` / `ECAT_EXPLICIT_PDO` / `ECAT_EXPLICIT_PROFILE` |
| `deploy/18-push-src.sh` | 打包清单加入 `config`（否则板端 app.conf 永远缺这几项） |

### 7.4 复测结果（`32-op-verify.sh`）

| 档位 | SM2/SM3 | AL | `0x6041` | `0x6064` | `0x6061` | 抖动 |
|------|---------|-----|----------|----------|----------|------|
| 1（3Rx+2Tx） | 7 / 6 | **OP** | `0x1650` | 170~174 | — | 3/12000 |
| 2（3Rx+3Tx） | 7 / 7 | **OP** | `0x1650` | 170~174 | `8`=CSP | 0/12000 |

### 7.5 经验沉淀

- **重启后必须 `ip link set eth0 up`**（已用 `deploy/33-persist-if-config.sh` 装成
  `kx-ecat-if.service` 固化，并顺带把 IRQ 绑到 CPU3）。
- **测 AL 状态别用 `ethercat slaves -v`**：读 SII 会抢 PDI 访问权，把 OP 中的从站打回 PREOP。

  指定位宽直读（`ecrt_master_sdo_upload`）。
- 远程执行：本机脚本用 `./deploy/bg.sh <log> <cmd>`；
  板端脚本用 `./deploy/run_bg.sh deploy/xx.sh <log> [参数]`（避免长任务被执行器跳过）。

## 8. M2 排障实录：CiA402 使能 + PP 走位

目标：真实 `EthercatMaster` + `Axis` + `Cia402Axis` 全链路跑通使能与点位。工具 `tools/ecat_axis.cpp`，
脚本 `deploy/36-build-m2.sh`（板端 g++ 直编）、`37-m2-verify.sh`（只使能）、`38-m2-move.sh`（走位）。

### 8.1 第一次 `37-m2-verify.sh` rc≠0 → 三个根因

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| ① | 20s 上限被 `timeout` 打断，收尾去使能没写完 → rc≠0 | 退出走 `OBSERVE→…→DISABLE` 相位机，收尾 200 拍耗时没预算 | 收尾改为**独立循环**（主循环退出后单独跑 200 拍），并在脚本里给 `timeout` 留足余量 |
| ② | 使能时 `sw` 读到 `0x0000/0x0800`，写控制字无效 | `ethercat` 服务刚起、从站还在 **PREOP**，工具却在 OBSERVE 2s 后直接使能 | 工具改为**等从站进 OP 且稳定 500ms** 后再发使能：`o.enable && bus_said && (now-bus_since)>=500ms` |
| ③ | 并发跑两个实例，`Failed to reserve master: Device or resource busy` | 残留进程 + 重试 | 脚本先 `pkill -f 'ecat_axis\|ecat_probe\|kine-x'`；`RETRIES=1` 防重复 |

### 8.2 档位选择：走位必须用**档位2**

档位1（`0x1A00={6041,6064}`）**未映射 6061**，门控只能超时 → PP 报错。
档位2 的 TxPDO 含 `0x6061`，走位正常。`38-m2-move.sh` 默认 `PROF=2`。

其余经验：

- **不要用 `ethercat slaves -v` 在运行中读 SII**：会抢 PDI 访问权，把 OP 中的从站打回 PREOP（§7.5 已述，M2 再次踩到）。

### 8.4 PV 点动与急停（实机全 PASS）

实现落在 `tools/ecat_axis.cpp`，新增 CLI/相位：

| 参数 | 作用 |
|------|------|
| `--jog MM_S` | PV(`6060=3`) 点动速度（隐含 `--enable`，自动把 `--profile` 升到 2） |
| `--jog-secs N` | 点动持续秒数（默认 2） |
| `--estop` | 点动加速到速后下发急停（`6040.bit8` halt）；未给 `--jog` 时复用 `--speed` |

相位机：`ENABLING → JOG_RUN →(到时) JOG_STOP / (急停) ESTOP_HOLD → DISABLE → DONE`。

**为什么 `60FF` 走 SDO 而不是 PDO**

- 档位3（Rx 含 `0x60FF`）实测被从站拒绝 → AL `0x001E`（见 §7）。
- 档位1/2 的 `0x1600` 只映射 `{6040,607a,6060}`，**没有 60FF**。
- 故：`6060/6040` 走 PDO，`0x60FF` 由独立 SDO 线程按“值变化才发”下发（`g_vel_req`/`g_vel_sent` 信箱），
  RT 线程仍保持无阻塞。PV 前提是 `6061==3` 回显，因此**必须档位2**。

**判定标准（工具自检）**

| 项 | 判据 |
|----|------|
| PV 点动 | 进入 PV 后 `6064` 位移 > 0.1mm（`检出运动`） |
| 减速停止 | 速度归零后连续 500ms 位移 < `0.05mm`（`点动已停稳`） |
| 急停 halt | halt 后 1.0~1.5s 残余漂移 ≤ 0.2mm，且 `6040.bit8=1` |
| 急停响应时间 | 逐拍差分 `6064`：halt→`\|v\| ≤ max(0.5, 2%·v0) mm/s` 用时（`急停响应` 行）+ 该段位移 + 平均减速度 |

**实机结论（2026-09-23，档位2 + DC 0x0300）**

| 场景 | 命令 | 实测 | 结论 |
|------|------|------|------|
| 正向点动 | `40-m2-jog.sh 5 2 jog` | 使能 95ms；`6061=3`；`60FF=+70217`；`0.0278 → 9.5173mm`（≈9.49mm/2s）；停稳 | PASS ✔ |
| 反向点动 | `40-m2-jog.sh -5 2 jog` | `60FF=-70217`；`12.9251 → 3.4358mm`（≈−9.49mm/2s）；停稳 | PASS ✔ |
| 减速停止 | 同上（`60FF=0` 后） | 连续 500ms 位移 <0.05mm 判稳 | PASS ✔ |
| **急停 halt（强验证）** | `40-m2-jog.sh 5 2 estop` | 见下 | PASS ✔ |

急停强验证细节：`STOP` 下发时**刻意保持 `0x60FF=+70217 inc/s` 不变**（只靠 `6040.bit8` 停车），
实测 `halt@12.9185mm` 后**停止距离 0.0152mm**、`1.0~1.5s 残余漂移 0.0000mm`，
控制字 `0x010f`（bit8=1、低 4 位仍为 `0x0F` 使能态）。

> 意义：证明 halt 能**独立**压过速度环命令，是可用作 `CANCEL/急停` 的硬停手段；
> 且 halt 叠加不破坏使能时序（低 4 位保持 `0x0F` 由 `cia402_test` 的"急停位叠加"用例保证）。
> 记录：档位2 下 `60FF` 走 SDO（`sdo_thread`），RT 周期 `滞后 0 拍`，1ms 无丢拍。

**急停响应时间（新增，已实测）**

`tools/ecat_axis.cpp` 的 `ESTOP_HOLD` 相位已加入逐拍差分测速：PDO 未映射 `606Ch`，故用 `6064h`
位置差近似瞬时速度，记录 `halt` 下发拍 → `|v|` 首次 ≤ `max(0.5, 2%·v0)` mm/s 的用时，
并据此算平均减速度 `v0 / t`。日志形如：

```
[m2] 急停响应：halt→|v|<0.50 mm/s 用时 9.0 ms，该段位移 -0.0054 mm（v_inst=0.00 mm/s）
[m2]     响应时间 9.0 ms（v0=1.00 mm/s → |v|=0.00 mm/s），平均减速度 ≈ 111 mm/s²
```

**实测（`42-m2-estop-time.sh 1 5`，2026-09-23）**：

| `v0` | 响应时间 | 停止距离 | 残余漂移 | 平均减速度 |
|---|---|---|---|---|
| 1 mm/s | **9.0 ms** | 0.0021 mm | 0.0000 mm | ≈111 mm/s² |
| 5 mm/s | **13.0 ms** | 0.0355 mm | 0.0001 mm | ≈385 mm/s² |

判读：9~13 ms（约 9~13 个 1ms 周期）远优于 20 ms 关注线；
若 >20ms，查 `605Dh`（halt 方式，默认 1，实读=1 ✔）/`6084h`·`609Ah`（减速度）/`H0E.34`。

## 9. 手册对照定案（SV630 手册 md 知识库）

依据 `/home/ubuntu20/Kine-X/SV630N_手册_EtherCAT学习笔记.md`（§9/§14/§15/§16/§17.2）与
ZBasic 手册抽出文本（`pdf_out/example_tcp_plumber.txt`），把此前标 ⏳ 的项逐条定案：

| 项 | 旧理解 | 定案（依据） |
|---|--------|--------------|
| 急停（`6040.bit8`）停机方式 | 由 `605Ah` 决定 | **由 `605Dh` 决定**（默认 1：`6084h/609Ah` 斜坡 + 位置锁定）；`605Ah`（默认 2）只管 `6040.bit2=0` 快速停机；`605Ch`（默认 0）管伺服 OFF。手册 md §9 |
| `603Fh` 报警码 | 唯一码 | **会重复**，唯一键须用 **`203Fh`**(Uint32)；`603Fh` 仅可粗判。手册 md §14 |
| 报警码全量 | 无 | 故障 **111** 条 + 警告 **31** 条（含 `603F/203F` 对照）。手册 md §16 |
