## 1. `svc-tcp` —— 4321 ASCII 服务（原任务1）

- 实现：POSIX socket `bind/listen/accept`，多客户端串行处理；`SO_REUSEADDR`。
- 解析：以 `;` / CR / LF 结尾成命令；**无结束符且空闲 200ms 按完整命令执行**（`CMD_IDLE_MS`）。
- 应答：一律以字面 `/n`（两字符）结尾；心跳每 2s 发 `beat/n`。
- 命令表（**保持原样**）：

| 命令 | 应答 |
|------|------|
| `HELLO;` | `HELLO ZMC` |
| `EN;` / `DIS;` | `OK` |
| `VJOG,<轴>,<速度>;` | `OK` / `ERR:NOBUS` |
| `STOP;` | `OK` |
| `MA,<轴>,<位置>,<速度>;` | `OK` |
| `MR,<轴>,<距离>,<速度>;` | `OK` |
| `STA;` | `STA,<bus_ok>,0,<MPOS>,<DPOS>,<IDLE>,` + `/n` |
| `<位置>;` | `move_done` / `move_error` / `busy` |
| `<acc>,<spd>,<pos>;` | `move_done` / `move_error` / `busy` |
| `SCAN;` / `BUSSTOP;` | `OK` |
| `W;` | `WEIGHT:<值>` / `ERR:NOSCALE` |
| `WSTA;` | `WSTA,通讯正常,数据有效,连接,结果,错误计数,重量,原始值,内码,零点内码` |
| `WT;` / `WTC;` / `WZERO;` / `WCLR;` | `OK` |
| `WDIV,<系数>;` / `WSA,<站号>;` | `OK` / `ERR:ARG` |
| `RSTA;` | `RSTA,连接,通讯,报警,错误计数,报文数,最近报文,MOTOR,RUN,ESTOP,MODE,FAULT,COLL,TASK` |
| `RCMD,<内容>;` / `RMON,<n>;` | `OK` / `ERR:ROBOT` / `ERR:ARG` |
| `RON;ROFF;RSTART;RSTOP;RMAIN;RCLEAR;RAUTO;RMAN;RDRAG;RUDRAG;RLIST;RCUR;` | `OK` / `ERR:ROBOT` |
| `RLOAD,<工程名>;` | `OK` / `ERR:ROBOT` / `ERR:ARG` |
| `PSTA;`（**新增 2026-09-27**） | 蠕动泵状态行：`PSTA,连接,通讯OK,控制方式,运行,转速rpm,流速,错误码` |
| `RSOCK,<0\|1>;`（**新增，v0.8.7**） | `OK` / `ERR:ROBOT` / `ERR:ARG`——映射机器人 `xCore::SocketInterface::Disable/Enable`（手册 `10.3.3` 控制命令 1/2）；**机器人无返回值**，发送后不等应答 |

> **命令对齐核验（2026-09-26）**：本表命令与应答已与旧 ZMC 逐条对照（含连接横幅 `HELLO ZMC SERVER 4321/n`、
> 成帧 `;/CR/LF` + 空闲 200ms 视为完整命令、所有应答字面 `/n` 结尾、心跳 `beat/n` 2s、move 判据 `0.05mm/10s`）——**机器人作为 4321 客户端即按本表使用**；
> 502 从站自 2026-09-28 起为**多客户端**（触摸屏 + 机器人等可并发，最多 4 个；见 `planA/19`）；4321 仍为单客户端（触摸屏不占用，PC 工具与机器人错开接入）。

- `move_done/move_error` 判据（沿用旧逻辑）：运动结束（`IDLE!=0`）后延时 200ms，
  若 `alarm=0` 且 `|MPOS - 目标| <= 0.05mm` 则 `move_done`，否则 `move_error`；
  超过 `MV_TIMEOUT` 视为超时 → `move_error`。运动中重复运动命令 → `busy`。
- ⭐ 旧 `SCAN;/BUSSTOP;` 对应 IgH 的重新 `activate` / 停总线，可实现为软重连（`bus_ok` 置 0→重扫）。
- `STOP;`（旧 `RAPIDSTOP`）语义已定案：置 `6040.bit8=1`（halt），停机方式由驱动器 `0x605D`（实读 **1 = 减速停**）决定，
  与 `0x605A` 无关；实测响应 **9.0~13.0ms**（v0=1/5 mm/s，`04` §8、`07` §8.4）。

## 2. `svc-modbus` —— 502 Modbus-TCP 从站（原任务2）

> **原实现状态（增量9 已完成，代码已移除）**：曾在 `src/svc_modbus/` 实现、以 `tools/svc_modbus_test.cpp` 自测；
> 该代码现已从工程删除，本节仅保留协议对照。原计划用 `libmodbus`，实际为**自研 MBAP 从站**（FC 03/04/06/16），
> 从而去掉对 `libmodbus-dev` 的运行库依赖，对外行为（地址/字序/站号/状态位）与旧程序一致。

- 实现：`socket` + `poll()` 单线程事件循环，自解析 MBAP 头（`tid/pid/len/unit`）与 PDU；
  03 与 04 映射同一 4x 读区；06 单写、16 多写；越界 `0x02`、非法功能 `0x01`、数量非法 `0x03`；
  站号不符的请求**不回应答**（与原逻辑一致）。可选 `MODBUS_MAX_CLIENTS` 个并发连接。
- 线程：约 5ms 轮询一次（`MODBUS_POLL_MS`），把共享状态写入 4x 寄存器、把写区命令取出执行。

  脚本先按旧约定 `int16 ÷10` 读，若 <1 再读低字在前浮点（`reg_get_f`）；两者都不足 1 才回落默认速度。
  ⚠ 注意：屏端浮点占 `4x65`（高字），该布局下旧“模式寄存器 `4x65`（0=绝对/1=相对）”不再可用（非 1 一律按绝对处理）；点动侧 `4x70` 原未用、无冲突。
- **点动方向（2026-09-27 修复）**：`4x68` 是 int16（屏端 **1=正 / -1=负**，负值在线上为 `65535`），脚本读取时先做**符号还原**再判方向
  （此前 `dir < 0` 恒不成立 → 恒正转）。
- 写区上升沿：`4x60`（使能/去使能/急停/重扫）、`4x66`（运动触发）、`4x67`（点动启动/停止）、
  `4x134`（称重命令 1/2/3/4）均按 **0→1 上升沿**触发一次，与旧 `mb_cmdold/mb_trigold/mb_jogold/scale_cmdold` 一致。
- 32 位字序：**低字在前**（低字在低地址；2026-09-26 触摸屏实测定案，与旧 ZMC `MODBUS_IEEE` 一致）。
  屏端/客户端字序设置必须与此一致，否则位置非零时显示 `####` 或极大值；原「高字在前（1234）」的记载已废弃。
- 非写区寄存器一律只读：`refresh_read_regs()` 只刷新读区，绝不覆盖写区命令寄存器。

## 3. `svc-scale` —— 称重 Modbus-RTU 主站（原任务3）

> **原实现状态（增量7 已完成，代码已移除）**：曾在 `src/svc_scale/` 实现、以 `tools/svc_scale_test.cpp` 自测；
> 该代码现已从工程删除，本节仅保留协议对照。原实现采用 **手工 RTU 组帧 + 自写 CRC16（$A001/$FFFF）**，未引入 `libmodbus`。

- 链路：TCP Client → `192.168.1.80:10123`（网关**纯透传**，网上跑原始 Modbus-RTU 字节）。
- ⚠️ **不能用 `libmodbus` 的 Modbus-TCP**（它按 MBAP 解析）。要**手工 RTU 组帧**，移植原逻辑：
  - 帧 = 站号 + 功能码 + 数据 + CRC16（低字节在前）；
  - CRC：标准 CRC16（$A001/$FFFF）；脚本层可用内置函数 `CRC16(数组[,起点,数量])`（见 `08`/`10`）。
  - 读 4 个寄存器：`01 03 00 00 00 04 <CRC>` → 应答 `01 03 08 <重量4> <内码4> <CRC>`。
  - 32 位低字在前；`值 = 高字*65536 + 低字`（负数用 `(hi-65536)*65536+lo`）。
  - 写单寄存器(06)：去皮 `0x0015`、零点校准 `0x0016`、写保护 `0x0017=1`、站号等。
- 粘包/分包重组、帧头非法重同步、超时计数、断线重连：全部按原逻辑实现。
- 备选（可选）：把称重模块直接接鲁班猫2 板载 RS485（`/dev/ttyS*`，9600 8N1），
  用 `libmodbus` RTU 主站即可，去掉网关、少一条以太网依赖。

## 4. `svc-robot` —— 机器人 TCP 客户端（原任务4）

> **⚠ 2026-09-28 起：本节描述的 4320 Socket 链路已取消**——机器人改为 **Modbus TCP 直连（502 多客户端）**，
> 语义/地址/桥接见 `planA/19`；本节保留为历史对照（`R*` 命令、报文后缀、旧启动时序等均不再存在）。

### 4.1 链路与参数

| 项 | 值 / 语义 |
|---|---|
| 方向 | **控制器（TCP 客户端）→ 机器人（TCP 服务端）**，`192.168.1.221:4320` |
| 端口句柄 | `ROBOT_CH=12`（编号仅句柄；新平台无「通道不够」问题） |
| 报文结束符 | **`\n`**（脚本常量 `ROBOT_SUFFIX`；必须与机器人侧「通信→外部通信→后缀」一致，本站=`\n`；手册 `10.3.2` 出厂图示亦为 `\n`） |
| 开机延迟 | `ROBOT_BOOT_WAIT=20s`（等机器人启动后再连） |
| 重连 | 断线每 `5s` 重试（`ROBOT_RECONN_MS`） |
| 轮询 | 连上后每 `500ms` 轮询监控表一条（`ROBOT_POLL_MS`）；控制命令优先插队 |
| 应答超时 | `2s`（`ROBOT_TIMEOUT`；`RSOCK` 为无返回值命令，不计超时） |
| 拆包 | 按 `LF / CR / ;`；数值解析兼容「带字段名」与「纯值」；`true/false` 直解 |
| 机器人侧设置 | HMI「通信 → 外部通信」：**服务端**、端口 `4320`、后缀 `\n`（手册 `10.3.2`，p.156） |

### 4.2 对外命令（4321）见 §1

**两条链路（勿混）**：

| 链路 | 控制器角色 | 对端（客户端/服务端） | 走向 | 主要功能 |
|---|---|---|---|---|
| **4321**（ASCII） | **服务端** | **机器人（客户端）**（PC/调试工具亦可） | 机器人 → 控制器 | **控制伺服电机运动**：机器人作为 4321 客户端直接连控制器下发运动命令（`STA/MA/MR/VJOG/…`） |
| **502**（Modbus-TCP） | **从站** | **触摸屏 IT7000**（唯一 HMI 链路） | 触摸屏 → 控制器 | HMI 命令字/寄存器读写；显示 4x140~149（机器人状态等）。**触摸屏与控制器只走 502** |
| **4320**（socket，手册 10.3） | **客户端** | **机器人（服务端）** | 控制器 → 机器人 | **监控机器人状态 + 控制机器人**：触摸屏在 502 侧下命令 → 控制器转发 4320（R* → 手册 10.3.3 字符串）；机器人应答写回 4x140~149 |

链路全景：

```
触摸屏 IT7000 ──502 读写──▶ 控制器
                              ▲  │
机器人 ──4321 客户端（控伺服）─┘  └──4320（控制器=客户端，机器人=服务端）──▶ 机器人
```

> 说明：**4321 的常驻客户端是机器人**（控制伺服）；触摸屏**不占用** 4321（只走 502），所以 4321 现有**单客户端**实现足够。
> PC/调试工具要用 4321 时需与机器人错开（或先断开一侧）。若将来需要「机器人 + PC」同时接入 4321，再扩展为多客户端
> （旧 ZMC 的 4321 为多客户端串行处理，可作对齐目标）。

机器人相关的**对外（4321）命令**（HMI/上位机 → 控制器）统一列在 **§1 命令表**：
`RSTA;`、`RCMD,<内容>;`、`RMON,<n>;`、`RON/ROFF/RMAIN/RSTART/RSTOP/RCLEAR/RAUTO/RMAN/RDRAG/RUDRAG/RLIST/RCUR;`、
`RLOAD,<工程名>;`、`RSOCK,<0|1>;`（新增，v0.8.7）。

⚠️ 区分要点：**4321 是控制器自己的对外 ASCII 协议**（原任务1，触摸屏/上位机用）；手册 p.156~158 描述的是
**机器人侧（4320）接口**——机器人作服务端时上位系统（=本控制器）发给它的字符串。控制器把命令**发往 4320**，
再把机器人应答**写回 4x140~149 寄存器（触摸屏经 502 读）与 4321 应答（RSTA/RMON/RCMD）**；机器人不直接连触摸屏。

### 4.3 发往机器人（4320）的报文

以下字符串即**手册 `10.3.3` 交互指令**：控制器（TCP 客户端）发往机器人（4320，服务端）的报文，末尾统一补 `\n`。

- **监控 12 条**（序号 0~11，顺序不变，前 4 条映射触摸屏）：`motor_on_state / robot_running_state / estop_state /
  operating_mode / home_state / fault_state / collision_state / task_state / cart_pos / jnt_pos / jnt_vel / jnt_trq`。
  手册另有 4 条 `*_name` 变体（带字段名前缀，如 `"cart_pos : "`、`"Jnt_vel : "`），本站未启用——解析器两种格式都兼容。
- **控制 15 条**（手册 p.157 四列表）：上表 12 条 + `load_prog` + `SocketInterface::Enable/Disable`。
- **单位/语义要点**（手册 p.158 备注）：`cart_pos` 含 x,y,z(mm)、a,b,c(度)、q1~q4(四元数)；`jnt_pos` 轴角 rad（导轨 m）；
  `jnt_vel` rad/s（导轨 m/s）；`jnt_trq` 为**电机额定力矩的千分比**；`task_state` 取 `ready/jog/load_identify/
  dynamic_identify/drag/program/demo/rci/debug`。
- **报警汇总**：`fault_state` / `collision_state` 为真即报警；`estop_state` 按机器人「急停触发电平类型」解释
  （`ROBOT_ESTOP_HIGH=1` 默认：高电平时 true=急停；置 0 则低电平时 true=非急停）；报文命中关键字 `fault` 亦置报警。
  ⚠️ 忠实于原 `robot_stv()`：某监控量**必须已收到过有效值**才计报警。

### 4.4 触摸屏/上位机寄存器映射（4x 读区，含数据类型）

### 4.5 Modbus → 机器人（4320）控制映射（4x 写/读区，2026-09-27 新增）

> 设计：**成对命令共用一个寄存器（0/1 状态式，值变化时下发）**；**单动命令一命令一寄存器（写 1 触发）**；
> **执行状态一状态一寄存器（布尔）**。同拍多条命令 → 按寄存器号**逐拍下发**（发送槽空闲才取下一个，不丢命令）。
> 本区是**命令区**；实际状态请看读区 4x143~4x150（`motor_on_state`/`running`/`operating_mode`/…）。

**成对命令（写，uint16 0/1，值变化触发）**

| 寄存器 | 1 表示 | 0 表示 |
|---|---|---|
| **4x151** | 启动socket接口 `xCore::SocketInterface::Enable` | 关闭socket接口 `xCore::SocketInterface::Disable` |
| **4x152** | 启动程序 `start`（**启动时序**：先 `pp_to_main`，机器人回 `true` 后**再等 `ROBOT_START_DELAY_MS`（默认 500ms）**才补发 `start`——等 PP 走完/状态稳定，避免紧接被拒；回 `false`/超时/断链则不发——结果见 4x201 与 4x161~167） | 停止程序 `stop`（直接下发） |
| **4x153** | 电机上电 `motor_on` | 电机下电 `motor_off` |
| **4x154** | 切换至自动 `switch_mode:auto` | 切换至手动 `switch_mode:manual` |
| **4x155** | 打开拖动 `open_drag` | 关闭拖动 `close_drag` |

**单动命令（写，uint16 布尔；0→1 沿触发一次，重复先写 0）**

| 寄存器 | 命令 | 寄存器 | 命令 |
|---|---|---|---|
| **4x156** | 清除伺服报警 `clear_alarm` | **4x159** | 获取当前工程 `current_prog`（文本→4x176/177~200） |
| **4x157** | 程序指针到main `pp_to_main` | **4x160** | 切换工程 `load_prog:<工程名>`（名字取 4x168~4x175） |
| **4x158** | 获取工程列表 `list_prog`（文本→4x176/177~200） | | |

**执行状态（读，uint16 布尔，4x161~4x167；同一时刻至多一个为 1）**

| 寄存器 | 状态 | 寄存器 | 状态 |
|---|---|---|---|
| **4x161** | 执行中（等待应答） | **4x165** | 未连接（未发出） |
| **4x162** | **成功/完成**（回 true；无返回值命令发送即置位） | **4x166** | 参数错误（工程名为空） |
| **4x163** | **失败**（回 false） | **4x167** | 不支持（保留） |
| **4x164** | 超时（2s 无应答） | | |

**数据区 / 标志**

| 寄存器 | 读写 | 数据类型 | 说明 |
|---|---|---|---|
| **4x201** | 读 | uint16 **布尔** | **`pp_to_main` 结果标志**（2026-09-27 新增）：机器人回 `true`→**1**、回 `false`→**0**；发送 `pp_to_main`（4x157）时先清 0（待应答）；**收到启动（4x152=1，启动时序开始）时也清 0**，回 `true` 后脚本立即补发 `start`（该 `start` 的 `true/false` 更新 4x161~167，不动 4x201） |
| **4x168~4x175** | 写 | 8×uint16 = **16 字节 ASCII** | 工程名（低字节在前；NUL(0) 截断、去首尾空白）；4x160 时取用 |
| **4x176** | 读 | uint16 长度 | 最近一次文本应答的字节数（0..48） |
| **4x177~4x200** | 读 | 24×uint16 = **48 字节 ASCII** | 文本应答缓冲（4x158/159 的返回，低字节在前，不足补 0） |

所有拒绝/失败都不伪装；`RCMD` 字符串透传仍只走 4321（§4.2），4320 报文表（§4.3）不变。
4x158 仍为「获取工程列表」触发位（未改动）；`pp_to_main` 结果标志独占 **4x201**（首个空闲寄存器）。

> **命令写队列派发（2026-09-27 现场定案）**：4x151~160 的派发改为「**按 Modbus 写入顺序的写队列**」——
> 同一主循环内收到成对写入（屏瞬时按钮 `1`→`0` 两帧在同一批 TCP 数据里）时，中间值不再被最终值覆盖
> （现场 20:04 实测：`4x155=1` 开拖动与 `4x154=1` 切自动都被随后同一批的 0 吞掉、只派发了 0）。
> 队列按写入顺序各按原值处理，再叠加回弹去抖；值变化扫描仅作自测/直写兜底（去重后不会重复触发）。

> **启动时序在途防重（2026-09-27 现场定案）**：启动时序进行中（pp_to_main 待应答 / 等 start 延迟 / start 在途）时，
> 重复写 4x152=1 一律忽略并记日志（现场 20:18:54 双击导致两条 pp_to_main 序列叠加）。

> **按钮回弹去抖（2026-09-27 现场定案）**：汇川屏**瞬时按钮**「按下写 1、松开写 0」——那个回弹 0 曾被当「停止」
> 紧跟 `pp_to_main` 下发（还会顶掉其应答），导致启动失效（现象：按启动后机器人无反应、指针不到 main；日志可见
> `HMI写 4x152=1` 后立刻 `=0`、无「启动时序」行）。脚本常量 `ROBOT_IGNORE0_MS`（默认 **1000ms**）：「开」派发后
> 该窗口内的 0 写入视为按钮回弹**忽略**（日志明示）。注意：启动后 1s 内按「停止」可能被忽略，重按一次即可。

> **写区触发语义（2026-09-27 现场定案）**：4x151~160 采用「**写入事件**触发」（Modbus FC6/FC16 每次写入都计数；
> 重复写同值也重新触发），而非仅盯值变化——汇川 IT7000 对**未变化**的标签**不会发送写入**（现场实测：
> 4x152 停在 1 时再按「启动」，屏侧吞掉、控制器零写入、机器人无指令）。因此**现场操作规范：
> 重新启动前先按「停止」（写 0）再按「启动」**；若把屏的启动按钮配成「每次按下都写 1」，写事件触发可直接支持连按。
> （不能由控制器自动回写 4x152=0 复位：那样「停止」按钮写 0 也会被屏吞掉、停止失效。）

> **机器人指令节流（2026-09-27）**：脚本常量 `ROBOT_CMD_GAP_MS`（默认 **50ms**）限制两条机器人报文的**最小间隔**
> （控制命令与监控轮询共用发送槽；监控轮询本身 500ms 不受影响）；启动时序的 `start` 另加
> `ROBOT_START_DELAY_MS`（默认 **500ms**）延迟。现场曾出现同一操作 `start` 时 true 时 false——多为
> `pp_to_main` 后 PP 尚在行走/状态未稳，紧接 `start` 被拒；如需调整这两个常量改脚本后推送（或告诉我改默认值）。

> **启动时序现场排错（2026-09-27 实测记录）**：`4x152=1` → 日志 `启动时序：先发 pp_to_main` → 回 `true` 后补发 `start` →
> 若机器人回 **`false`**（日志 `[robot] 启动结果：false`），表示**机器人拒绝启动**——按时序正常、非后缀/通讯问题
> （`pp_to_main` 的 `true` 能正常收到）。常见原因（手册 p.157 备注与 xCore 状态约束）：**不在自动模式**、
> **有绑定暂停功能的寄存器/系统IO未复位**、**未载入工程**。排错读点：`4x146` 工作模式（1=自动）、
> `4x143` 电机上电、`4x159` 当前工程（`current_prog`）；必要时 4321 `RCMD,current_prog` / `RCMD,list_prog` 复核。

## 8. `svc-pump` —— 蠕动泵（485/透传网关；2026-09-27 起，2026-09-28 功能完善）

- **设备/链路**：保定创锐 M 基本型蠕动泵 = **RS485 Modbus-RTU 从站**（8N1、默认 9600、站号 1~31 出厂 1；
  **★本站现场实测站号 = 4**，脚本 `PUMP_STATION=4`，2026-09-27 用原始帧扫描 0~20 确认）；
  与称重**同款链路形态**：控制器 TCP 客户端 → 透传网关 `192.168.1.81:10123`，线上即 485 原始字节；
  脚本自组 RTU 帧（站号+功能码+数据+**CRC16 低字节在前**，与称重共用 `crc16/rtu_frame`）。
  协议细节与实例见根《保定创锐蠕动泵通讯规约_学习笔记.md》§0（现场实测记录）。
- **关键差异（必守）**：
  1. **上电/重连必须先写保持寄存器 0=1 使能 485 控制**（掉电不存储；未使能时写操作回异常 04 且 reg50=3）；
     脚本连上后自动写，并使能**自动重试**（`ctl≠2` 时每 3s 重发，直至 485 通讯控生效）；
  2. 泵 FLOAT = **高字在前**（与触摸屏 502 的“低字在前”相反）——脚本收发两侧转换，镜像给 HMI 用
     `reg_set_f`（低字在前）；
  3. 业务错误码统一读**输入寄存器 50**（Modbus 层异常几乎恒为 04，须再读 reg50 定位）；
  4. 输入 0~5 应答解析须**按寄存器对齐**（reg0 ctl 2B / reg1 dir 2B / reg2~3 rpm FLOAT / reg4~5 flow FLOAT，
     每寄存器 2 字节 big-endian）——2026-09-27 实测修正（曾按紧凑字节错位，流出乱码）；
  5. **按圈数/按容积运行前会先把 4x204 设定转速下发给泵**（否则泵按内部旧转速走、计时与实际不符）。
- **已实现**（脚本 `pump_step`；端口句柄 `PUMP_CH=14`、任务号 5）：
  连接/重连、485 使能（含自动重试）、状态轮询（控制方式/方向/转速/流速/运行/reg50）、
  命令码 4x203（启停/写转速/重新使能/全速）、回吸参数读写（4x215/217/219 ↔ 泵 reg7/8）、
  **按圈数运行**（4x211/213）、**按容积运行**（4x221 ml/圈、4x214 输送管数量、4x225 设定容积、4x227 预计圈数、4x229 运行）、
  体积换算（4x223 预计出液量，保留 1 位小数）、`PSTA;` 诊断（含 REVS/SET/ANG/SPD/MLREV/VOL/TVOL/PREV）。

| **4x219** | 写 | uint16 | **回吸参数提交**：写 1 下发泵 reg7/reg8（自动回 0） |
| **4x221/222** | 写 | float32（低字在前） | **ml/圈**（每转出液量；掉电保存） |
| **4x223/224** | 读 | float32（低字在前） | **预计出液量（ml，1 位小数）** = 4x211 × 4x221 × 4x214（ml/圈先按 3 位小数规整） |
| **4x225/226** | 写 | float32（低字在前） | **设定容积（ml）**（掉电保存）；**现场屏该元件 ×10 → 控制器 ×0.1 还原（`VOL_IN_SCALE`）** |
| **4x227/228** | 读 | float32（低字在前） | **预计圈数（1 位小数）** = 4x225 ÷ 4x221 ÷ 4x214；ml/圈=0 时显示 0 |
| **4x229** | 写 | uint16 | **容积运行按钮**：写 1 → 圈数=容积÷ml/圈÷4x214，按 4x213 同款机制（先下发转速）定时运行（自动回 0） |

> **屏输入参数掉电保持（三类，详见 `planA/18` §0）**：
> ① **控制器 `.nvram`**：**4x64/65、69/70、71、72、73、130/131、132/133、204、211/212、214、221/222、225/226**（`NVSET/NVGET`，写即落盘、脚本 init 恢复；重装/重启/换屏都能恢复；清单=脚本 `NVRAM_REGS`）；
> ② **设备内保持**：4x215/217（回吸，存泵内）、称重校准（存模块内）——上电自动读回；
> ③ **不保持**（重启回默认）：轴 4x60~70 速度、4x28~31 校准计数、4x130/131/132/133 称重参数、机器人/泵运行态等。
