# 01 架构与硬件网络

## 1. 硬件清单

| 项 | 型号/规格 | 说明 |
|----|-----------|------|
| 主控 | 鲁班猫2（RK3568，4×Cortex-A55） | 运行 Debian 12（`lubancat-rk3568-debian12-lite-20260422`），内核 `6.1.99-rk356x`（**PREEMPT_VOLUNTARY，未打 RT 补丁**，见 `02` §2） |
| EtherCAT 网卡 | **板载 `eth0`**（SoC `rk_gmac-dwmac`） | IgH 无原生驱动 → 用 **`generic`**；当前无 PCIe 网卡 |
| 业务网口 | **板载 `eth1`**（SoC `rk_gmac-dwmac`） | 触摸屏/PC/机器人/称重网关 |
| 伺服 | 汇川 SV630（EtherCAT 型） | 保留原有，单轴 |
| 存储 | eMMC 启动 | 系统盘 |
| 供电 | 24V → DC-DC 5V/12V | 与驱动器共地，注意隔离 |

> ✅ **实测结论**：本机**未使用 PCIe i210**，两个网口都是 SoC 的 `rk_gmac-dwmac`，IgH 只能用 `generic`（链路层直发）。
> 因此**板载口做 EtherCAT 的抖动风险上升**，必须靠 `isolcpus` + 中断亲和 + `threadirqs` 等手段压制（已在 `02` §2 落地并实测）。
> `generic` 驱动下 EtherCAT 帧会在 TCP/IP 栈旁路直接收发，但网卡本身仍走 Linux 驱动 → 抖动**必须实测**。
>
> 📌 若实测抖动不达标，再考虑插 PCIe i210（IgH `igb` 原生驱动，抖动最低）。

## 2. 双网口划分（关键）

```
eth0 ── EtherCAT 专用（NetworkManager unmanaged，无 IP，默认 DOWN）
        └── 汇川 SV630 CN4(IN)                      ← IgH generic 驱动接管，仅运动线程用
eth1 ── 业务/管理网 192.168.1.0/24（出厂固定静态，控制器 IP 192.168.1.11，不用 DHCP）
        ├── PC 上位机（4321 客户端）
        ├── 汇川 IT7000 触摸屏（502 Modbus 主站）
        ├── 机器人 192.168.1.221:4320
        └── 称重网关 TAS-LAN-869 192.168.1.80:10123
```

> ⚠️ **业务口 = 出厂固定静态 IP**：板端 `eth1` 出厂即固定为 `192.168.1.11/24`（`08-net-separate.sh` 的 `HOUSE_IP`），
> **不使用 DHCP**——避免每台控制器地址漂移、每次都要去路由器上查。SSH 与上位机均走该地址。
> 这样 PC/触摸屏/机器人/网关天然同网段，无需再切换到"调试网"。

**规则：**
1. EtherCAT 口与业务口**物理分离**，禁止把 EtherCAT 口设 IP 或桥接。
2. `motiond` 只绑定 EtherCAT 网卡做 RT 线程；业务 socket 只走 eth1。
3. 若设备总数多，业务网加一个普通交换机即可。
4. EtherCAT 网口在 Linux 侧**保持 DOWN / 无 IP**属正常；运行时由 EtherCAT 主站 `ip link set up` 后独占（见 `deploy/13-pin-irq.sh`）。

## 3. SV630 EtherCAT 接线与新旧端口对照

`板载 eth0` ──RJ45──▶ `SV630 CN4(ECAT IN)`；`CN5(ECAT OUT)` 空（单轴总线到此终止）。

> ⚠️ 实机 `H0E.29=0x0000000B`：**CN4(IN) 口链接丢失 11 次**（OUT 口 0）→ 上现场前检查 CN4 侧网线/端子（见 `07` §9.1、手册 md §17.5）。

| 用途 | 旧（ZMC） | 新（鲁班猫2） | 备注 |
|------|-----------|---------------|------|
| PC ASCII 命令 | 4321，ECUSTOM 10 | TCP Server 4321（POSIX socket） | 协议不变 |
| HMI Modbus 从站 | 502，固件 ETH | Modbus-TCP Server 502（自研 MBAP 从站） | 寄存器映射不变 |
| ZDevelop 在线调试 | 500，固件 ETH（厂商私有协议） | 自研调试口 `DEBUG_PORT=5000`（JSON-Lines，绑业务网、开机自启） | **不复刻 500**（不运行 ZDevelop），见 `13` §4.3 |
| ZDevelop 在线 | 500 | 无（改用 ssh / 调试日志） | 不再需要 ZDevelop |
| 称重网关 | TCP Client，ECUSTOM 11 → 192.168.1.80:10123 | TCP Client（POSIX socket）+ 手工 RTU 组帧 | 可保留网关或改板载 485 |
| 机器人 | TCP Client（通道不够，原为占位） | TCP Client → 192.168.1.221:4320 | ⭐新平台通道无限制，此瓶颈消失 |
| EtherCAT | 控制器内部 | 板载 `eth0` + IgH Master（`generic` 驱动） | 单轴，DC SYNC0 1ms |

> ⭐ 原项目因 ZMC `max_ethcustom=2` 导致机器人链路拿不到通道（README 第八节）；
> 鲁班猫2 上 socket 数量无限制，**该历史问题自然消除**，机器人链路可直接落地。

## 6. 与原代码的模块对应关系

| 原 ZBasic 模块 | 新模块 | 类型 |
|----------------|--------|------|
| 任务0 总线初始化 + 输入口调试 + 看门狗 | `motiond`（IgH + CiA402 + 运动内核） | RT 线程 |
| 任务1 `socket_task` | **脚本层**（BASIC / Lua，`src/script/`） | 脚本线程 |
| 任务2 `modbus_task` | **脚本层**（`MODBUS_REG` 读写 `Shared::mb_regs`） | 脚本线程 |
| 任务3 `scale_task` | **脚本层**（`PortManager` TCP 通道 + 自组帧） | 脚本线程 |
| 任务4 `robot_task` | **脚本层**（`PortManager` TCP 通道 + 轮询状态机） | 脚本线程 |
| `in0~in7/in22/in23` 调试输入 | `libgpiod`（可选）或去掉 | 可选 |
| `PROC_STATUS` 看门狗 | systemd `Restart=always` + 进程内线程守护 | — |

> 注：原 4 个原生服务（`svc-tcp`/`svc-modbus`/`svc-scale`/`svc-robot`）曾按此表实现，
> **现其代码已从工程移除**，任务1~4 改由**脚本层**承担（协议对照见 `05`，范围界定见 `12`）。
