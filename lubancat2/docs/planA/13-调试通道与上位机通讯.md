# 13 调试通道与上位机通讯（方案）

> 定位：解决「**用什么通道让调试软件/上位机在线访问控制器**」这一**架构选型**问题。
> 本文只做**方案整理与选型结论**，**尚未实施**（无 `DebugServer` 代码）。
>
> 边界（与 `12-范围与边界.md` 一致，切勿混淆）：
> - **业务/协议通道**（4321 ASCII、502 Modbus、称重、机器人）→ 归**脚本层**（`12` 已定）；
> - **调试通道**（脚本下载、单步、变量监视、状态订阅）→ 归 **C++ 层**，独立于脚本引擎。
>
> 换掉原系统 ZDevelop 的「**500 端口在线调试**」（旧→新的一行记录见 `05` §6）是本方案的目标；
> 它属于里程碑 M7（调试软件后端，`README` §三）的**对外通道延伸**。

---

## 1. 先分清楚：业务通道 ≠ 调试通道

两条链路的诉求完全不同，**不能混在一条协议里**：

| 维度 | 业务/协议通道 | 调试通道（本文） |
|------|----------------|------------------|
| 面向对象 | 上位机 PC、IT7000 触摸屏、机器人、称重网关 | 调试软件（ZDevelop 类 IDE）/ 工程师 |
| 通道内容 | 固定命令表（`EN;` `MA,…;` `STA;`、4x 寄存器） | 脚本上传、运行/停止/单步、变量读写、状态订阅、日志 |
| 数据方向 | **请求 → 应答** | 请求 → 应答 **＋ 主动事件推送**（本质差异） |
| 稳定性诉求 | 长期在线、字段一字不差（兼容性硬约束） | 随调试会话建立/断开，可增强演进 |
| 归属层 | **脚本层**（`12` §5） | **C++ 层**（见下） |
| 兼容约束 | 必须与旧系统 1:1（`README` §一） | 无历史包袱，可自定 |

> ⚠️ **调试通道必须内建在 C++，不能交给脚本层。**
> 否则出现「自举死锁」：脚本编译失败 / 跑飞时，恰恰是最需要调试它的时刻，
> 而调试器本身也依赖那个脚本——闭环断了。
> 这正是「协议对接归脚本、调试归 C++」的分界线所在。

## 2. 现状：已具备的能力与缺口

**好消息**：语言无关的引擎接口 `IScriptEngine`（`src/script/engine.h`）**已经按「调试软件后端」设计**，
调试所需的原语大多就绪，缺的只是「对外通道」和少数引擎增强。

| 调试能力 | 现状 | 现有接口 / 位置 |
|----------|------|------------------|
| 编译 / 运行 | ✅ | `IScriptEngine::compile(src,err)` / `run(max_steps)` |
| 状态 / 错误 / 行号 / 步数 | ✅ | `status()` / `error()` / `error_line()` / `steps()` |
| 中止 | ✅ | `request_abort()`（线程安全，仅置位） |
| 变量查看 / 预置 | ✅ | `get_var` / `set_var` / `list_vars` / `clear_vars` |
| 单步跟踪（逐条打印） | ✅（打印式） | `set_trace(bool)` / `trace()` |
| 位置列表（断点/跳转表） | ✅ | `labels()`（BASIC=标签；Lua=函数/行号表） |
| 双语引擎（BASIC / Lua） | ✅ | `name()` 返回 `basic`/`lua`；`engine_rule.h` 强制二选一（`09`） |
| **对外通讯通道** | ✅ | `debug_server.{h,cpp}`（TCP JSON-Lines，随服务自启，`DEBUG_PORT`） |
| **脚本热更新** | ✅ | `ScriptEngineSlot::create_staged/replace` + `script.compile{p.swap:true}` |
| **断点 / 暂停 / 继续** | ✅（BASIC） | `add/remove/clear_breakpoints` + `request_pause/step/resume`（语句边界协作式） |
| **事件推送 / 订阅** | ✅ | `subscribe`/`unsubscribe` + `script`/`log`/`axis`/`bus`/`mb` 事件 |
| **日志外送** | ✅ | `MotionHost::set_output` → `log` 事件（未订阅也推） |

**结论**：做一个「通道 + 少量引擎增强」即可，而非从零造调试器。

**归纳出三种范式：**

| 范式 | 代表 | 优点 | 缺点 |
|------|------|------|------|
| ① 文本行协议 | ZDevelop / S7 | 实现最快，`nc` 即可验证 | 表达力弱、无推送、解析易歧义 |
| ② 二进制 TLV | ADS / CODESYS | 高效紧凑 | 客户端需专用库，开发成本高 |
| ③ **JSON-RPC over TCP/WebSocket** | Moonraker / gRPC 生态 | 可读、可推送、Web UI 直接可用、跨语言 | 报文略大（对调试场景可忽略） |

## 4. 推荐方案

### 4.1 选型结论

> **在 C++ 内建一个独立「调试服务器」线程，走 JSON-Lines over TCP（每行一条 JSON），
> 可选在同套 schema 上叠 WebSocket；与 4321 业务端口分离、与 RT 线程完全隔离、以订阅代替轮询。**

理由：

1. 调试场景对带宽不敏感，**可读性/可调试性**优先（③ 优于 ②）；
2. **事件推送**是调试的刚需（曲线、状态面板），JSON-Lines + 订阅天然支持；
3. 同套 schema 可再包一层 WebSocket，**浏览器直接当调试台**（参考 Moonraker / Duet）；
4. 与现有 `IScriptEngine` 接口一一对应，改造成本最低。

### 4.2 总体架构

```
调试软件 (桌面 App / 浏览器 Web UI)
        │  TCP :<DEBUG_PORT>   JSON-Lines（每行一条 JSON：req / resp / event 三类）
        ▼
┌──────────────────── kine-x 进程 ────────────────────┐
│  DebugServer 线程（普通优先级，poll 非阻塞，谁用谁推进）  │
│    · RPC 分发 ──► IScriptEngine（compile/run/step/var…）│
│                ├─► Shared 只读快照（轴状态/总线/寄存器）  │
│                └─► 配置 / 日志 / 系统信息                │
│    · 事件推送（订阅式，如 20Hz；非轮询）                  │
│         ▲ 只读快照        │ 命令槽（与脚本同一条路）        │
│  ───────┼─────────────────┼─────────────────────────── │
│  RT 线程（1ms，SCHED_FIFO 99，CPU3）← 绝不参与调试 IO      │
│  SDO 线程 / 脚本线程（可选）                              │
└───────────────────────────────────────────────────────┘
```

要点：

- DebugServer 复用 `Shared` 的**只读快照**（与日志线程同一路），**不进 RT 线程**（同 `04` 的隔离原则）；
- 下发动作（运动/变量）经**命令槽**，与脚本线程**同一条路**，避免两套语义；
- 单进程多线程模型不变（`README` §二）。

### 4.3 端口与信道

| 端口 | 用途 | 归属 | 备注 |
|------|------|------|------|
| 4321 | 上位机 ASCII 业务 | 脚本层 | 兼容性硬约束，见 `05` §1 |
| 502 | 触摸屏 Modbus-TCP | 脚本层 | 见 `05` §2 |
| 10123 / 4320 | 称重（出）/ 机器人（出） | 脚本层 | 见 `05` §3/§4 |
| **`DEBUG_PORT`（本项目取 5000，可配）** | **调试通道** | **C++ 层（本文）** | 绑**业务网**（`0.0.0.0` / `192.168.1.11`），局域网 PC 直连；**开机自启**，见 §4.5 |

> **为什么是 5000 而不是旧系统的 500？** 二者不是一回事，别混：
> - **500** = 旧控制器上 **ZDevelop 厂商私有在线协议**的固定端口（即 `ZBasic文档.md` / `README.md` 里的
>   「ETH 通道在线」）。新控制器**不运行 ZDevelop**，且本文调试口是自研 **JSON-Lines** 协议，
>   与 500 的报文格式**不兼容**，所以**不复刻 500**。
> - **5000** = 本项目**自定**的调试通道端口（配置项 `DEBUG_PORT`，号码可改）。取 5000 是为了与
>   500/502/4321 在语义上**明确区分**，避免现场把「插件连的是我们自己协议」误当成「ZDevelop 在线可用」。
>
> **部署形态（重要）**：**调试插件（VSCodium 扩展）只运行在 PC 上，控制器板端不装插件、不跑 VSCodium**。
> 调试口是**服务端**：板子开机即监听，等**局域网内任意一台 PC** 的 VSCodium 插件来连（PC 上填 `192.168.1.11:5000`）。
> 因此**不能默认绑 `127.0.0.1`**——那只有板子自己连得上，与「用另一台电脑远程调试」的用法矛盾。

- **不复用 4321**：调试需要「同一连接上双向推送 + 多主题订阅」，与 4321 的「一问一答、字面 `/n` 结尾」
  语义冲突；硬塞进去会破坏旧上位机的解析假设。
- `DEBUG_PORT` 配置纳入 `config/app.conf`（键名如 `DEBUG_ENABLE` / `DEBUG_PORT` / `DEBUG_BIND`），
  与既有 `SCRIPT_*` 配置风格一致；**默认开机启用**（随 `kine-x.service` 自启），`DEBUG_BIND` 默认绑业务网卡。

### 4.4 消息模型（三类，一条连接全承载）

**① 请求 → 应答**（`id` 关联；`ok` 区分成败）：

```jsonc
{"id":1,"m":"auth","p":{"token":"..."}}               // 可选：连接**首帧**鉴权（见 §4.5）；未启用 token 时省略
{"id":1,"ok":true,"r":{}}

{"id":2,"m":"sys.info"}
{"id":2,"ok":true,"r":{"ver":"...","engine":"auto","axis_count":1}}   // engine: basic|lua|auto|mixed

{"id":3,"m":"script.compile","p":{"src":"...","engine":"basic"}}
{"id":3,"ok":true,"r":{"labels":["loop","done"]}}      // 失败: {"ok":false,"err":{"line":12,"msg":"..."}}

{"id":4,"m":"script.run"}
{"id":4,"ok":true,"r":{"status":"READY"}}

{"id":5,"m":"script.step"}                            // 单步（需引擎增强，见 §5.2）
{"id":6,"m":"var.list"}         {"id":6,"ok":true,"r":["SPEED = 100","POS = 12.5"]}
{"id":7,"m":"var.set","p":{"name":"SPEED","v":100}}
{"id":8,"m":"axis.snapshot"}
{"id":8,"ok":true,"r":{"bus_ok":1,"mpos":12.5,"dpos":12.5,"idle":1,"enabled":1,"alarm":0}}

{"id":9,"m":"cmd","p":{"line":"STA"}}                 // 终端：执行单条设备命令（经 MotionHost）
{"id":12,"m":"sys.restart"}                           // D7：重启控制器（异步执行 DEBUG_RESTART_CMD）
{"id":12,"ok":true,"r":{"restarting":true}}           // 应答先回，随后服务重启并断开连接
{"id":13,"m":"boot.get"}                              // D8：查主文件（开机运行）
{"id":13,"ok":true,"r":{"dir":"/userdata/kine-x/scripts","name":"main.bas","valid":true}}
{"id":14,"m":"boot.set","p":{"name":"main.bas"}}      // 设主文件（文件必须已存在）
{"id":14,"ok":true,"r":{"name":"main.bas","valid":true}}
{"id":15,"m":"boot.clear"}                            // 取消主文件（回退 SCRIPT_FILE）
{"id":15,"ok":true,"r":{"name":""}}
```

> `sys.info.engine` 取值 `basic` / `lua` / `auto` / `mixed`：调试口的脚本语言由 `DEBUG_SCRIPT_DIR`
> 内**现有脚本**推导（2026-09-25 拍板）——空目录 = `auto`（两种语言都可编译，首次带 `name` 落盘后绑定）、
> 只有一种 = 绑定它、两种并存 = `mixed`（拒绝新编译，提示先删除一种）。**不需要在板端配置语言**；
> 自动脚本（`SCRIPT_ENABLE=1`）的语言与调试口目录绑定**相互独立**：设了 `.boot` 主文件时按主文件扩展名，
> 否则回退 `SCRIPT_FILE` + `SCRIPT_ENGINE`；同一时刻仍只允许一种语言（自动脚本在跑时调试口只报 `d1`）。

**② 订阅**（把轮询变成推送）：

```jsonc
{"id":10,"m":"subscribe","p":{"topics":["axis","bus","log"],"hz":20}}
{"id":10,"ok":true,"r":{"sub":["axis","bus","log"]}}
{"id":11,"m":"unsubscribe","p":{"topics":["log"]}}
```

**③ 事件推送**（服务端主动，无 `id`）：

```jsonc
{"e":"axis","t":12345,"mpos":12.5,"dpos":12.5,"idle":1}
{"e":"script","t":12346,"status":"DONE","steps":8123}
{"e":"log","t":12347,"s":"[script] loop=3","lvl":"info"}
```

- `t` = 毫秒时间戳（单调时钟），供曲线对齐；
- 事件频率由订阅 `hz` 限频，默认不宜过高（20Hz 足够观感，避免刷屏与锁竞争）。

### 4.5 线程、隔离与安全

| 项 | 约定 |
|----|------|
| 线程 | 独立 `DebugServer` 线程，**普通优先级**（非 RT）；`poll` 非阻塞，风格同 `PortManager`（谁用谁推进） |
| 隔离 | 只读 `Shared` 快照；下发经命令槽；**绝不触碰 `ecrt` / RT 线程**（同 `04`、`12`） |
| 挂起 | 单步/断点挂起的是**脚本线程**（条件变量），**不是 RT 线程** |
| 绑定 | 默认绑**业务网卡**（`DEBUG_BIND`：`0.0.0.0` 或 `192.168.1.11`），供局域网 PC 直连；跨网段或需加固时再用 **SSH 端口转发** |
| 部署形态 | 插件（VSCodium 扩展）**只装在 PC 上**；板端不装插件、不跑 VSCodium。调试口随 `kine-x.service` **开机自启**，是常驻**服务端** |
| 鉴权 | 可选一次性 token，**连接首帧** `{"id":1,"m":"auth","p":{"token":"..."}}`：成功 `{"ok":true,"r":{}}`；失败 `AUTH_FAILED`。服务端未实现该方法时应回 `UNKNOWN_METHOD`（插件据此按「未启用鉴权」放行，向前兼容）。多客户端策略待定（§9） |
| 背压 | 事件通道满时丢弃最旧事件并计数，**绝不阻塞** RPC 路径 |

## 5. 需要补齐的工程点（按依赖排序）

### 5.1 脚本热更新（在线下载）（**已实装**）

实现（`script.compile` 带 `p.swap=true`，`ScriptEngineSlot::create_staged/replace`）：

1. 用 `create_staged()` 造一个**同语言新引擎实例**（不碰运行中的实例）；
2. 新源码在暂存实例上编译：**失败 → 丢弃暂存实例，运行中脚本毫发无损**（回 `COMPILE_ERROR` + `err.line`）；
3. 校验通过 → `slot_.replace(staged)` **原子替换**槽内指针，回 `{labels, swapped:true}`；
4. 对旧实例 `request_abort()`（会 `notify_all` 唤醒可能的 D5 挂起），其 worker 线程退出后
   `release_retired()` 才真正 `delete`——**join 之前绝不释放**，避免 worker 踩野指针。

> ⚠️ 绝不可在旧实例上**原地重编译**：半编译态会污染正在运行的脚本。
> ⚠️ `swap` 判定必须**先于** `run_th_.join()`：worker 可能正挂在断点上，先 join 会让热更新永远等不到。
> 需注意 `ScriptHost`（`MotionHost`）的共享与线程安全：新实例复用**同一个** `host_`（单槽语义不变）。

### 5.2 断点 / 暂停 / 继续（**已实装；BASIC 语句级 / Lua 行级**，v0.8.0 起两引擎均支持）

实现（`src/script/script.cpp` 的 `Impl::dbg_gate` + `debug_server.cpp` 的 6 个 RPC）：

- 引擎在**语句边界**（`exec_stmt` 入口）调用协作式闸门 `dbg_gate(line)`：
  命中断点 / 收到 `request_pause()` 即挂在 `std::condition_variable` 上，直到
  `resume()` / `request_step()` / `request_abort()` 唤醒（`request_abort` 会 `notify_all` 防死锁）；
- 控制器侧方法：`script.pause` / `script.resume` / `script.step` / `breakpoint.add|del|list`；
- **挂起的是脚本 worker 线程，绝不碰 RT 线程**；`script PAUSED` 事件带 `line`（当前执行行）；
- 断点粒度**仅行号**（`breakpoint.add {line}`；`{label}` 形式不支持）；
  `breakpoint.del` 无参 = 清空全部（DAP `setBreakpoints` 全量替换语义）；
- `IScriptEngine` 新增 D5 原语的**默认空实现**，故 Lua 引擎无需改动；
  Lua 引擎下 D5 方法明确回 `NOT_SUPPORTED`（`sys.info.caps` 也不报 `d5`）。

> 状态前置不满足（未运行 / 未挂起）统一回 `BAD_PARAM`，`msg` 说明原因
> （协议错误码表未设状态类码，见 `16` §9.6）。

### 5.3 日志外送

现状：日志只落 stdout / systemd journal。

需要：给日志加一个 **hook**，`log` 订阅时把行实时推给调试通道（限频、环形缓冲）。

### 5.4 订阅快照

现状：`Shared` 已有发布机制（RT 循环 ~100ms 发布一次，见 `main.cpp`）。

需要：DebugServer 侧读取快照 + 限频推送；**不新增 RT 侧开销**。

## 6. 与现有接口的映射（改造面很小）

| 调试功能 | 直接对接现有接口 |
|----------|------------------|
| 编译 / 运行 / 停止 | `IScriptEngine::compile` / `run` / `request_abort` |
| 状态 / 错误 | `status` / `error` / `error_line` / `steps` |
| 变量监视 / 预置 | `get_var` / `set_var` / `list_vars` / `clear_vars` |
| 单步（打印式，先做） | `set_trace(true)` + `print()` 落点转发 |
| 断点列表 | `labels()` |

> （`Shared::mb_used`，256 位）；`mb` 事件在 `start`/`regs` 之外恒带 `used`＝4×16 位十六进制（字第 i 位=寄存器 i，

> 插件 Modbus 面板据此高亮已用单元格并提供「仅显示已用」过滤。

> AL 状态 1=INIT 2=PREOP 3=BOOT 4=SAFEOP 8=OP。
> **D9 端口数量上限（v0.8.5，方案 A）**：端口编号 0..上限-1 只是句柄（`PortManager::kMaxSlots=64` 静态容量，
> `kDefaultMaxPorts=16` 出厂默认）；`port.max.get` 回 `{max, slots, default, dir, used[]}`；`port.max.set {max}`
