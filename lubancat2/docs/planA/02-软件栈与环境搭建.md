# 02 软件栈与环境搭建

## 1. 软件栈选型

| 层 | 选型 | 理由 |
|----|------|------|
| OS | Debian 12 arm64（鲁班猫2 官方镜像 `lubancat-rk3568-debian12-lite-20260422`） | 生态好、IgH 可编译 |
| 内核 | 现状 `6.1.99-rk356x`（**PREEMPT_VOLUNTARY，非 RT**）；可选加强：自编 PREEMPT_RT | 见 §2；当前用「启动参数 + 运行时调优」把抖动压到 1ms 周期可接受范围 |
| EtherCAT 主站 | **IgH EtherLab Master 1.5.2/1.6** | 成熟、内核态、支持 DC、原生网卡驱动 |
| 运动 | 自研 C++（CiA402 + 梯型规划器） | 单轴足够 |
| Modbus | **自研（手工组帧，无第三方依赖）** | 从站(502，MBAP) + RTU 主站(称重)，见 `05`；初版计划用 `libmodbus`，已去掉 |
| 网络 | 原生 POSIX socket（或 `asio`） | 4321 / 机器人 |
| GPIO（可选） | `libgpiod` | 替代原 in0~in7 调试输入 |
| 进程守护 | systemd `Restart=always` | 替代 `PROC_STATUS` 看门狗 |

## 2. 实时化方案（已实施）

> ⚠️ **与初版计划的重要差异**：初版打算自编 `5.10 + PREEMPT_RT`，实际板子跑的是官方
> `6.1.99-rk356x`（**PREEMPT_VOLUNTARY，非 RT**）。当前策略改为
> **「内核启动参数 + 运行时调优 + 总线/业务网口分离 + systemd 持久化」**，
> 已实测把 1ms 周期抖动压到 Max ≈ 0.5ms（见 §2.3）。是否自编 RT 内核见 §2.5。

### 2.1 板端现状（实测）

| 项 | 实测值 |
|----|--------|
| 系统镜像 | `lubancat-rk3568-debian12-lite-20260422` |
| 内核 | `6.1.99-rk356x #8 SMP ... aarch64`（PREEMPT **VOLUNTARY**） |
| DTB | `rk3568-lubancat-2-v2.dtb` |
| 关键内核配置 | `PREEMPT_VOLUNTARY=y`、`HZ=300`、`NO_HZ_IDLE`、`PREEMPT_DYNAMIC=n`、`NO_HZ_FULL=n`、`IRQ_FORCED_THREADING=y`、`RCU_NOCB_CPU=y`、`CPU_ISOLATION=y`、`RT_GROUP_SCHED=y` |
| 时钟源 | `arch_sys_counter` |
| **启动入口** | **`/boot/uEnv/uEnv.txt`**（软链 → `uEnvLubanCat2-V2.txt`） |
| CPU | 4×Cortex-A55（cpu0~3） |

> 📌 **`/boot/extlinux/extlinux.conf` 在本机不生效**。boot.scr 用 `env import -t` 读取
> `uEnv.txt`，并把其中的 `cmdline=` 变量追加到 bootargs —— 所以内核参数必须写进 **uEnv.txt**。

### 2.2 已落地的配置项

内核启动参数（写入 uEnv.txt 的 `cmdline=`，**重启生效**）：

```
threadirqs skew_tick=1 isolcpus=3 rcu_nocbs=3
```

| 参数 | 作用 |
|------|------|
| `threadirqs` | 强制中断线程化（内核 `IRQ_FORCED_THREADING=y`）→ 中断线程可被 RT 线程抢占 / 可调优先级 |
| `skew_tick=1` | 错开各 CPU 的 tick 相位，避免 tick 同时打到一个核 |
| `isolcpus=3` | 把 CPU3 从通用调度器摘出，专供运动控制 RT 线程 |
| `rcu_nocbs=3` | CPU3 的 RCU 回调交给 kthread 在别的核执行，避免 softirq 打扰 |

> ❌ **不加 `nohz_full=3`**：内核未开 `CONFIG_NO_HZ_FULL`，加了也不会生效（避免误解）。

运行时调优（`deploy/05-tune-runtime.sh apply`，重启后由 `kine-x-tune.service` 自动重放）：

| 项 | 值 | 作用 |
|----|----|------|
| CPU governor | `performance` | 锁最高频（1992 MHz），消除调频延迟 |
| cpuidle | 仅保留 `state0`，关闭 `state1+` | 避免深度 C-state 唤醒延迟 |
| 中断亲和 | `eth0`(EtherCAT) IRQ → CPU3；其余 IRQ（含 `eth1`）→ CPU0-2 | 总线中断就近 RT 核，业务中断不打扰 RT 核 |
| `kernel.sched_rt_runtime_us` | `-1` | 解除 RT 带宽限制（默认 95%，超限会被节流） |
| `kernel.timer_migration` | `0` | 定时器不跨核迁移 |
| `kernel.nmi_watchdog` | `0` | 去掉 NMI watchdog 干扰 |
| `vm.swappiness` | `10` | 减少换页抖动 |
| `irqbalance` | 停用 | 改用手工中断亲和（避免它把 IRQ 挪到 CPU3） |
| `/etc/security/limits.d/99-kine-x-rt.conf` | `rtprio 99`、`memlock unlimited` | 非 root 用户（`cat`）可开 SCHED_FIFO |
| `realtime` 组 | 已创建并把 `cat` 加入 | 同上，配合 `SupplementaryGroups=realtime` |

网口分离（`deploy/08-net-separate.sh apply`）：

| 网口 | 角色 | 配置 |
|------|------|------|
| `eth0` | **EtherCAT 专用** | NetworkManager `unmanaged-devices`；Linux 不配 IP、默认 DOWN；offload(gso/tso/gro/lro/rx/tx/sg) 全关；由 IgH 接管 |
| `eth1` | **业务/管理** | 出厂固定静态 `192.168.1.11/24`（不用 DHCP；SSH 与上位机走这里） |

> 🔎 两个网口驱动都是 SoC 的 `rk_gmac-dwmac`，IgH 无原生驱动 → EtherCAT 只能用 **`generic`** 驱动。
> 这对应 `01` 文档里「无 PCIe 网卡时退用板载口」的退路。

systemd 单元（`deploy/09-tune-service.sh` / `10-install-service.sh`）：

- `kine-x-tune.service`：`oneshot` + `RemainAfterExit=yes`，开机重放 §2.2 全部运行时调优（**已 enable**）。
- `kine-x.service`：`User=cat`、`SupplementaryGroups=realtime`、`LimitRTPRIO=99`、
  `LimitMEMLOCK=infinity`、`CPUAffinity=0-3`、`IOSchedulingClass=realtime`，
  `ExecStartPre=/bin/bash /opt/kine-x/deploy/13-pin-irq.sh eth0 3 up`
  （先把 `eth0` 拉起，等 IRQ 出现后绑到 CPU3 —— 网口 down 时 `/proc/interrupts` 里看不到它的 IRQ）。

一键编排入口：`deploy/push.sh`（推脚本到 `/opt/kine-x/deploy`）→ `deploy/11-bootstrap.sh`（应用 ①网口分离 ②cmdline ③调优服务）→ `sudo reboot` → `deploy/12-verify.sh`（复核）。

### 2.3 实测抖动（cyclictest，`-S -p90 -i1000 -D 60`，单位 µs）

| 场景 | Min | Avg | Max | 说明 |
|------|-----|-----|-----|------|
| ① 未调优（基线，重启前） | 7 | ~41 | **915 / 887 / 1035 / 1084** | 默认 `ondemand` + `irqbalance` 在跑，深度 C-state 开启 |
| ② 运行时调优后·空闲 | 6 | 8~19 | **679 / 445 / 578 / 593** | `apply` 后未重启 |
| ③ 运行时调优后·加压 | 6 | 8~19 | **538 / 559 / 598 / 537** | 同跑 `hackbench -l 10000 -g 4` |
| ④ **重启后（持久化生效）·空闲** | **6 / 6 / 6** | **9 / 9 / 8** | **412 / 506 / 539** | `cmdline` + `kine-x-tune.service` 全生效 |
| ⑤ **重启后·加压**（`hackbench -l 10000 -g 4`） | **6 / 6 / 6** | **20 / 18 / 18** | **427 / 348 / 431** | 负载下 Max 反而略低于空闲 |

**结论**
- 调优后 Max 抖动由 **~1.1ms 降到 ~0.5ms**，Avg 由 ~41µs 降到 ~9µs，分布集中在 6~10µs（直方图峰值在 8µs）。
- 加 hackbench 压力后 Max 未恶化（甚至更低）→ 说明瓶颈不在业务负载，而在**非 RT 内核的临界区不可抢占**。
- 对项目约束「单轴、点到点定位 + 点动、1ms 周期」而言，**0.5ms 的偶发抖动可接受**（位置环在驱动器内部，控制器只下发目标/使能/点动速度）。

### 2.5 PREEMPT_RT 内核（✅ 2026-09-27 已实施并部署）

**结论：无需自编打补丁——野火官方维护 `LubanCat/KERNEL` 仓库分支 `lbc-develop-6.1-rt36`**（6.1.99-rt36 与 BSP 内核精确同源，RT 补丁已合入源码，defconfig 已开 `PREEMPT_RT=y + HZ_1000`）。

| 项 | 内容 |
|------|------|
| 构建 | PC 交叉编译（`aarch64-linux-gnu-gcc`），配置走**最小差异路线**：板上现役 config → RT 源码 `olddefconfig` → 翻转 `PREEMPT_RT/HZ_1000/PREEMPT_LAZY` → 再 olddefconfig（与现役内核总差异仅 ~100 行，全部为 RT 语义） |
| 部署 | 并排安装：`/boot/Image-6.1.99-rt36-rk356x` + `/lib/modules/6.1.99-rt36-rk356x-g3d027a80ff40-dirty/`（全为新名，不动现役文件）；DTB/initrd/overlay 复用现役（RT 补丁不改设备树） |
| 启动入口 | **`/boot/Image` 符号链接才是真正入口**（boot.cmd 优先 `/Image`，`Image-${uname_r}` 仅 fallback；`extlinux.conf` 未被使用，`uEnvLubanCat2-V2.txt` 为实际生效 uEnv）；切换=改链接 `ln -sf` |
| IgH 模块 | PC 交叉编译（IgH 源码 `--with-linux-dir=<RT内核树>` + `make ARCH=arm64 CROSS_COMPILE=... modules`），`ec_master.ko/ec_generic.ko` vermagic 与新内核精确匹配，装 `/lib/modules/<rel>/ethercat/` |
| 实测 | 绑隔离核 CPU3 cyclictest（FIFO95/1ms/30000 次）：**Max=12µs、Avg=1µs、零溢出**（旧内核 Max≈500µs）；kine-x RT 循环 jit≈50µs；EtherCAT OP/502/4321/称重/机器人全链路恢复正常 |
| 回退 | `sudo ln -sf Image-6.1.99-rk356x /boot/Image && reboot`（原内核与模块未动）；uEnv 备份：`/boot/uEnv/uEnv.txt.bak-orig-*`、`uEnvLubanCat2-V2.txt.bak-orig-*` |

### 2.6 参考：自编 PREEMPT_RT 内核步骤（历史记录，最终未走此路线——用野火 rt36 分支替代）

```bash
# 1) 取内核源码（版本必须与 RT 补丁一致）
git clone -b stable-6.1-rk356x <鲁班猫2内核仓库> linux-6.1
cd linux-6.1

# 2) 打 RT 补丁（版本号必须完全匹配：6.1.x-rtY）
wget https://cdn.kernel.org/pub/linux/kernel/projects/rt/6.1/patch-6.1.<x>-rt<y>.patch.xz
xz -d patch-6.1.<x>-rt<y>.patch.xz
patch -p1 < patch-6.1.<x>-rt<y>.patch

# 3) 在现有 defconfig 上打开 RT
make ARCH=arm64 lubancat_defconfig     # 名称以官方为准
scripts/config --enable PREEMPT_RT
scripts/config --enable PREEMPT_RT_FULL
scripts/config --enable HIGH_RES_TIMERS
scripts/config --enable HZ_1000

# 4) 编译并出 deb 包
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) deb-pkg
# 5) 板端安装
sudo dpkg -i linux-image-*.deb linux-headers-*.deb
```

启动参数（**写 `/boot/uEnv/uEnv.txt`**，不是 extlinux.conf）：

```
isolcpus=3 rcu_nocbs=3 irqaffinity=0-2 skew_tick=1
# 若该内核确实开了 CONFIG_NO_HZ_FULL，再加：nohz_full=3 rcu_nocb_poll
```

- 把 CPU3 隔离出来专供 RT 线程；RT 线程 `sched_setaffinity` 绑到 CPU3。
- 启动后确认：`uname -a` 含 `PREEMPT RT`；`cat /sys/kernel/realtime` 存在。

## 3. IgH EtherLab Master 编译安装（✅ 已在板上完成，版本 **1.6.13**）

### 3.1 关键结论：**只能在板上编译，不做 PC 交叉编译**

| 证据 | 说明 |
|------|------|
| 板上已有内核构建树 | `/lib/modules/6.1.99-rk356x/build` → `/usr/src/linux-headers-6.1.99-rk356x`（含 `Module.symvers`）→ 可直接编内核模块 |
| 本机（PC）无内核源码/headers | 交叉编译内核模块需要**与板端完全一致**的 6.1.99-rk356x 源码树 |
| 板端 headers 里的 host 工具是 aarch64 | `scripts/mod/modpost`、`scripts/basic/fixdep` 是 **aarch64 ELF static**，x86 上跑会 `Exec format error` |

→ 路线：**PC 只负责取源码（本机可访问 gitlab）→ 源码传板 → 板上 `make`**。
版本选 **1.6.13**（`devices/` 含 `-6.1-` 变体、NEWS 提到已适配 6.18，对 6.1.99 兼容）。

### 3.2 步骤（对应 deploy 脚本）

```bash
# ① 依赖（deploy/15-igh-deps.sh）
sudo apt install -y build-essential autoconf automake libtool pkg-config m4 \
     git patch bison flex bc rsync kmod

# ② PC 取源码并传板（deploy/push-igh.sh）；1.6.13 源码包：
#    https://gitlab.com/etherlab.org/ethercat/-/archive/1.6.13/ethercat-1.6.13.tar.gz
#    解压到 /opt/kine-x/ethercat

# ③ 板上编译安装（deploy/16-igh-build.sh）
./bootstrap
./configure --prefix=/usr/local \
  --with-linux-dir=/lib/modules/$(uname -r)/build \
  --enable-generic --enable-tool --enable-userlib \
  --disable-eoe --disable-8139too --disable-e100 --disable-e1000 --disable-e1000e \
  --disable-genet --disable-macb --disable-igb --disable-igc \
  --disable-r8169 --disable-stmmac-pci --disable-dwmac-intel \
  --disable-ccat --disable-rtdm --disable-initd \
  --with-systemdsystemunitdir=/lib/systemd/system
make -j$(nproc) all
make -j$(nproc) modules          # ⚠ 必须单独编！见 3.3
sudo make modules_install install
sudo depmod -a
sudo ldconfig                    # ⚠ 必须！否则运行时报 libethercat.so.1 not found
```

### 3.3 三个实测踩坑（务必记住）

| 坑 | 现象 | 原因 / 解法 |
|----|------|-------------|
| **① 内核模块不在 `all` 里** | `make` 报成功，但 `master/ec_master.ko`、`devices/ec_generic.ko` **不存在** | IgH 的 `master/`、`devices/` 的 `all` 目标是**空的**，内核模块必须显式 `make modules` |
| **② 缺 `ldconfig`** | 运行 `ecat_probe` 报 `libethercat.so.1: cannot open shared object file` | `libethercat.so` 装在 `/usr/local/lib`，需 `sudo ldconfig` 刷新缓存 |
| **③ 无参预加载 `ec_master` 会「锁死」主站** | `/dev/EtherCAT0` 不生成，`ethercat master` 报 `No such file or directory` | 主站设备由 `modprobe ec_master main_devices=<MAC>` 创建；若模块**已被无参加载**，后续带参数的 `modprobe` 会被当 no-op → 必须先 `rmmod ec_generic ec_master` 再由 `ethercatctl start` 启动 |

### 3.4 配置与启动（deploy/17-config-master.sh）

配置路径由 `ethercatctl` 决定：`--prefix=/usr/local` 时读 **`/usr/local/etc/ethercat.conf`**
（脚本会自动从 `ethercatctl` 里解析出该路径，并在 `/etc/ethercat.conf` 放同份便于查阅）。

```
MASTER0_DEVICE="8e:56:ce:3f:af:2b"     # eth0 的永久 MAC（addr_assign_type=0）
DEVICE_MODULES="generic"
```

> `MASTER0_DEVICE` 也可直接写网口名 `eth0` —— `ethercatctl` 内置 `parse_mac_address()`，
> 会用 `ip address show dev eth0` 自动解析出 MAC。
> ⚠ 启动前若 `ec_master` 已被无参加载过，脚本会先 `systemctl stop` + `rmmod` 再 `start`（见 3.3 坑③）。

```bash
sudo systemctl enable ethercat && sudo systemctl start ethercat
lsmod | grep ec_                     # 应看到 ec_master + ec_generic
ls -l /dev/EtherCAT0                 # 存在即主站已创建
sudo /usr/local/bin/ethercat master  # Master0 / Phase: Idle / Main: <MAC> (attached)
sudo /usr/local/bin/ethercat slaves  # 空 = 总线上还没有从站
```

## 5. systemd 守护（替代 `PROC_STATUS` 看门狗）

`deploy/kine-x.service`：

```ini
[Unit]
Description=Kine-X replacement (EtherCAT + services)
After=network-online.target ethercat.service
Wants=network-online.target

[Service]
Type=simple
ExecStartPre=/usr/local/bin/ecat_wait_op.sh        # 等 EtherCAT 到 OP（可选）
ExecStart=/home/ubuntu20/Kine-X/lubancat2/build/kine-x
WorkingDirectory=/home/ubuntu20/Kine-X/lubancat2
Restart=always
RestartSec=1
CPUAffinity=0-2
Nice=-5
LimitRTPRIO=99
LimitMEMLOCK=infinity

[Install]
WantedBy=multi-user.target
```

- RT 线程在程序内用 `pthread_setschedparam(SCHED_FIFO, 99)` + 绑核 CPU3。
- 任一业务线程崩溃 → 由 `main` 内守护重启；整个进程崩溃 → systemd 拉起。
- **调试口 `DEBUG_PORT=5000`（`DebugServer`）随本服务开机自启**，绑业务网卡（`DEBUG_BIND`），
  供**局域网内 PC** 的 VSCodium 插件直连（**板端不装插件、不跑 VSCodium**）——见 `13` §4.3/§4.5。
