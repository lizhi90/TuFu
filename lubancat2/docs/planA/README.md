# 方案 A 实施计划：鲁班猫2(Debian) + IgH EtherCAT 主站 替换 正运动 ZMC 控制器

> 目标：用「鲁班猫2（RK3568，Debian）」替换正运动 ZMC 控制器，保留原 EtherCAT 伺服驱动器（汇川 SV630），
> 以 **IgH EtherLab EtherCAT Master + 自研应用** 的方式，实现对原 `EtherCAT_SocketServer.bas` 全部功能的 1:1 替换。
> 项目约束：**默认单轴（`AXIS_COUNT=1`）、点到点定位 + 点动，实时要求不高**。运动内核已按**多轴**设计
> （编译期上限 8 轴、运行时 `AXIS_COUNT` 1..8、单域多从站），加轴仅需配置 `AXIS_COUNT` 与
> `ECAT_SLAVE_POS_<n>`；`AXIS_COUNT=1` 时行为与旧单轴版完全一致。
>
> 📁 **路径约定**：本项目所有新增文件（文档 / 配置 / 源码 / 构建 / 部署）统一放在
> **`/home/ubuntu20/Kine-X/lubancat2/`** 下；上级目录中的正运动原程序
> （`EtherCAT_SocketServer.bas`、`README.md`、`ZBasic文档.md` 等）**保持不动**，仅作参考与回退。

## 一、目标与不变量（Invariants）

替换过程中以下对外接口**必须保持不变**，保证上位机与触摸屏零改动、可双跑可回退：

| 接口 | 约束 |
|------|------|
| TCP 服务端 4321 ASCII 命令 | 命令字、参数格式、应答字面量（含 `/n` 后缀、`beat/n` 心跳）完全一致 |
| Modbus-TCP 从站 502 | 站号=1、4x 寄存器地址与字序、状态字位定义完全一致 |
| 称重链路 | 经 TAS-LAN-869 网关（192.168.1.80:10123，纯透传 Modbus-RTU）行为一致 |
| 机器人链路 | 控制器作 TCP 客户端连 192.168.1.221:4320，协议与监控轮询行为一致 |
| 轴单位 | 1 unit = 1 mm（`PULSE_EQUIV` 对应关系不变） |
| 业务网 IP | 鲁班猫2 业务口（`eth1`）出厂固定静态 `192.168.1.11/24`（不用 DHCP，避免地址漂移） |

**可变部分**：控制器内部实现、EtherCAT 主站软件、运动内核、语言与进程模型。

> ⚠ **本阶段范围**：上表是最终**兼容性目标**（对外接口必须一致）。但当前处于**控制器开发阶段**：
> 与机器人 / 触摸屏 / 称重的**具体协议对接暂不实现**——对应的 4 个原生服务
> （4321 / 502 / 称重 / 机器人）**代码已从工程彻底移除**（无 `src/svc_*`、无 `svc_*_test`、无构建开关），
> 计划在控制器完成后**由脚本程序实现**。详见 **`12-范围与边界.md`**。

## 二、总体架构

```
                        ┌────────────── 鲁班猫2 (RK3568, Debian 12 + 实时化调优) ───────────────┐
                        │  业务/管理口 eth1 (192.168.1.11, NM 管理)                             │
   PC 上位机 ──4321────▶│                                                                     │
   IT7000 触摸屏 ──502──▶│   ┌── 脚本线程（BASIC / Lua，二选一）    ← 协议对接层（后续实现）    │
  机器人 ──4320(Server)◀─│   │     · 4321 ASCII / 502 寄存器映射 / 称重 / 机器人             │
 称重网关 ──10123(Server)◀│  │     · 经 PortManager（TCP 通道）、Shared::mb_regs 等通用原语   │
                        │   │                                                                 │
                        │   └── motiond      运动内核 + IgH EtherCAT（原 任务0）              │
                        │                    ◀── 唯一硬实时部分，绑 CPU3                      │
                        │                           │                                          │
                        └───────────────────────────┼──────────────────────────────────────────┘
                                                    │ EtherCAT（独占板载 eth0，无 IP，NM unmanaged）
                                                    ▼
                                           汇川 SV630 伺服驱动器 ── 电机（默认单轴；多轴时每轴一从站）
```

- **进程模型**：单进程多线程（`motiond` 为独立进程/或独立 RT 线程），全局变量→共享内存/加锁，
  语义最接近原 ZBasic 的 `GLOBAL` + 多任务。
- **实时部分隔离**：仅 motion 线程需要 `SCHED_FIFO` + 绑核 + 1ms 周期；其余为普通线程。
- **本阶段范围**：图中 4321 / 502 / 称重 / 机器人 为**兼容性目标**，不在控制器实现；
  4 个原生服务**代码已彻底移除**，协议计划由**脚本线程**实现。控制器阶段只跑
  「运动内核 + IgH EtherCAT + 脚本宿主」（见 `12`）。

## 六、风险与回退

| 风险 | 缓解 |
|------|------|
| RK3568 板载网卡做 EtherCAT 抖动大 | 先按 `02` §2 做实时化调优（**已把 system 抖动压到 Max ≈ 0.5ms**）；若跑 OP 后仍丢帧，再插 **PCIe Intel i210**（IgH 有 `igb` 原生驱动，抖动最低），板载口只跑业务 |

## 七、实时化落地（M0，✅ 已完成）

**板端环境**：鲁班猫2 V2｜`lubancat-rk3568-debian12-lite-20260422`｜内核 `6.1.99-rk356x`（**PREEMPT_VOLUNTARY，非 RT**）｜DTB `rk3568-lubancat-2-v2.dtb`。

### 7.1 做了什么

| # | 内容 | 落地方式 |
|---|------|----------|
| 1 | **内核启动参数** `threadirqs skew_tick=1 isolcpus=3 rcu_nocbs=3` | 写入 `/boot/uEnv/uEnv.txt`（⚠️ 本机 `extlinux.conf` **不生效**）→ `deploy/06-cmdline.sh` |
| 2 | **运行时调优**：governor=performance、关 cpuidle 深睡眠、中断亲和（`eth0`→CPU3 / 其余→CPU0-2）、`sched_rt_runtime_us=-1`、`timer_migration=0`、`nmi_watchdog=0`、`swappiness=10`、停 `irqbalance` | `deploy/05-tune-runtime.sh` |
| 3 | **实时权限**：`rtprio 99` / `memlock unlimited` + `realtime` 组 | `deploy/05-tune-runtime.sh`（`/etc/security/limits.d/99-kine-x-rt.conf`） |
| 4 | **网口分离**：`eth0`=EtherCAT 专用（NM unmanaged、无 IP、关 offload）；`eth1`=业务/管理 | `deploy/08-net-separate.sh` |
| 5 | **开机自动重放调优** | `kine-x-tune.service`（oneshot，已 enable）→ `deploy/09-tune-service.sh` |
| 6 | **主程序 systemd 化**（RT 权限 + 崩溃重启 + 启动前绑 EtherCAT 网口 IRQ） | `kine-x.service` → `deploy/10-install-service.sh`、`deploy/13-pin-irq.sh` |

一键编排：`deploy/push.sh` → `deploy/11-bootstrap.sh` → `sudo reboot` → `deploy/12-verify.sh`。

### 7.2 实测抖动（cyclictest `-S -p90 -i1000 -D 60`，µs，3 个测试线程）

| 场景 | Min | Avg | **Max** |
|------|-----|-----|---------|
| 未调优基线 | 7 | ~41 | **915 / 887 / 1035 / 1084** |
| 运行时调优后·空闲 | 6 | 8~19 | 679 / 445 / 578 / 593 |
| 运行时调优后·加压 | 6 | 8~19 | 538 / 559 / 598 / 537 |
| **持久化生效后·空闲** | 6 | 9 | **412 / 506 / 539** |
| **持久化生效后·加压** | 6 | 20 / 18 / 18 | **427 / 348 / 431** |

**结论**：Max 由 **~1.1ms → ~0.53ms**，Avg 由 ~41µs → ~9µs；加压不劣化（瓶颈在非 RT 内核临界区，不在业务负载）。
对「单轴 PP 定位 + 点动 + 1ms 周期」的约束**满足**；若后续上 CSP / 多轴插补，再评估自编 `PREEMPT`/`PREEMPT_RT` 内核（见 `02` §2.5 / §2.6）。

### 7.3 回退

`deploy/05-tune-runtime.sh revert` ／ `06-cmdline.sh revert` ／ `08-net-separate.sh revert` ／ `09-tune-service.sh uninstall`；
原始值快照在板端 `/var/tmp/kx_rt_state/`（带 `.saved` 标记，不会被重复 `apply` 覆盖）。详细命令见 `02` §2.4。

### 7.4 踩过的坑（供复现者参考）

1. **`extlinux.conf` 改了没用** → 真正入口是 `/boot/uEnv/uEnv.txt`（boot.scr `env import -t` 追加 `cmdline=`）。
2. **内核没开 `NO_HZ_FULL`** → `nohz_full=3` 是无效参数，别加（`CPU_ISOLATION`/`RCU_NOCB_CPU` 有，`NO_HZ_IDLE`）。
3. **`eth0` down 时看不到它的 IRQ** → 必须在启动主程序时先 `ip link set eth0 up` 再绑亲和（`13-pin-irq.sh`）。
4. **`sched_rt_runtime_us` 默认 95%** → 不设 `-1`，RT 线程会被周期性节流，表现为"偶发大延迟"。
5. **一键 `apply` 的批量 IRQ 迁移会误伤 EtherCAT 口** → 迁移循环里必须排除 EtherCAT 网口的 IRQ。
