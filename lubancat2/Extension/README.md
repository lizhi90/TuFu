# Kine-X 调试（VSCodium 插件）

在 **VSCodium / VS Code** 里对 Kine-X 运动控制器做在线调试：脚本下载与运行、变量监视、
断点/单步、状态面板与实时曲线。全部通过控制器侧的**调试通道**（JSON-Lines over TCP）通信，
不需要在控制器上安装任何 Node 运行环境。

> 设计文档：`lubancat2/docs/planA/14-调试软件客户端方案.md`（方案）、`15-VSCodium插件需求与开发任务.md`（需求与任务）、
> `16-调试通道报文样例与Mock方案.md`（报文与 Mock）。

---

## 功能一览

| 分组 | 能力 |
|------|------|
| 连接 | 连接/断开控制器、查看控制器信息（`sys.info`）、状态栏指示、**意外断线自动重连**（指数退避，可关） |
| 重启 | 「控制器 → 重启控制器」：模态确认后 `sys.restart` 重启板端 `kine-x.service`（需控制器 `d7`），插件自动重连（≤20s） |
| 文件 | 侧边栏「控制器文件」**原生列表视图**（语言图标 + 大小 + **一致性标识**：控制器 `file.list.hash` ↔ 本地 `controller-sync/` 副本 → 一致/不一致/本地无副本/未比较；行内/右键可拉取、删除、**设为主文件**）；**同步/全部拉取**＝控制器 → 工作区（`controller-sync/`）；**下载**＝工作区 → 控制器（编译并落盘） |
| 多文件 | 控制器可存多个同语言脚本；**主文件（★）开机自动运行**，其它脚本由主文件 `INCLUDE "sub.bas"` / `include("sub.lua")` 作为子程序调用（需控制器 `d8`） |
| 编辑运行 | `.bas` / `.lua` 语法高亮（含命令名）与命令补全（**按签名生成参数占位**）、**Hover 签名/说明**、**签名帮助**、**代码片段**、下载/运行/停止、运行中热更新（需控制器 `d4`） |
| 诊断 | 编译错误（`err.line/msg`）落到 **Problems** 面板并定位到行；控制器引擎不符时**本地拦截**并给出改法 |
| 调试（DAP） | 断点、单步、暂停/继续（需控制器 `d5`；**BASIC 语句级 / Lua 行级均支持**）、变量树、监视、REPL（`evaluate`）；**调试会话与面板单客户端自动交接** |
| 面板 | 轴状态（DPOS/MPOS 均 4 位小数、可暂停刷新、**在线调试按钮**：使能/去使能/停止/点动/定位、**脉冲当量输入**）、Modbus 4x 寄存器（**已用寄存器监视**：已用高亮 + 「仅显示已用」过滤，v0.8.6）、EtherCAT 总线（编辑区独立 Webview 面板，工具菜单打开） |
| 控制器 | 重启控制器（D7）、**修改端口数量**（D9：端口上限 1..64，重启保留；有端口占用时拒绝收缩）、修改IP地址（含端口） |
| 通讯 | 「工具 → **通讯状态**」（D10）：对外连接列表（连接方式/用途、服务端/客户端、主/从、对方 IP、端口、连接状态）+ EtherCAT 主站与**每个从站明细**（身份/名称/轴/AL/在线）；面板可见才订阅 `conn` |
| 曲线 | 实时曲线 Webview：位置 MPOS/DPOS + **推算**跟随误差/速度，图例可显隐，**导出 CSV**、可清空 |
| 终端 | 设备命令执行（`cmd`），返回码与输出分离 |

**事件驱动、不轮询**：面板与曲线由控制器的订阅事件推送更新，界面不可见时不占用带宽。

## 安装

### 方式 A：离线 `.vsix`（现场无外网，推荐）

```bash
cd lubancat2/Extension
npm install          # 仅首次（打 VSIX 用）
npm run package      # 产出 kinex-debug-<版本>.vsix
tools/install-vsix.sh                 # 自动探测 codium/code 并安装
# 或指定： tools/install-vsix.sh --cli /usr/bin/codium
# 卸载：   tools/install-vsix.sh --uninstall
```

安装后**重启编辑器**，在命令面板（`Ctrl+Shift+P`）运行 **Kine-X 控制器: 连接控制器**。

> 脚本会自动探测 `codium` / `codium-insiders` / `code` / `code-insiders`；找不到时用 `--cli` 指定。

### 方式 B：命令行直接安装 VSIX

```bash
codium --install-extension kinex-debug-0.4.8.vsix --force   # VSCodium
code   --install-extension kinex-debug-0.4.8.vsix --force   # VS Code
```

### 方式 C：Open VSX（需外网）

```bash
OVSX_PAT=xxxx tools/publish-ovsx.sh          # 维护者发布
```

用户在 VSCodium 扩展市场搜索 **“Kine-X 调试”** 安装/更新。

## 快速上手（5 步）

1. **打开工作区**，新建脚本 `demo.bas`（或 `.lua`）。
2. **连接**：命令面板 → `Kine-X 控制器: 连接控制器`。先输 **IP**、再输**端口**（两步都就地校验，
   任一步取消即中止）。默认值取上次输入，其次是设置 `kine-x.host` / `kine-x.debugPort`。
3. **写脚本**，例如：

   ```basic
   PRINT "hello kine-x"
   SPEED = 100
   MOVE(0) 100
   WAIT IDLE
   ```

4. **下载并运行**：命令面板 → `Kine-X 调试: 下载并运行`（或编辑器右上角 ▶）。
   编译错误会在 Problems 中定位到具体行。
5. **看状态/文件**：左侧活动栏 **Kine-X** 图标 = 控制台（菜单栏 + 状态行）+ **控制器文件**列表视图；
   轴状态 / Modbus 寄存器 / 曲线在编辑器区独立面板打开（工具菜单或命令面板 `Kine-X 调试: 打开…`）。
   「下载」成功后脚本会出现在文件列表；点击文件行（或行内「拉取」按钮）即拉取到工作区 `controller-sync/`，
   行内/右键「删除」可删除控制器文件（删空目录会让脚本语言回到「自动」）。

## 命令与菜单

命令面板（`Ctrl+Shift+P`）里的命令按两个分组归类：

| 分组 | 条目 |
|------|------|
| `Kine-X 控制器` | 连接控制器、断开连接、同步（控制器 → 工作区）、**重启控制器**（需控制器 `d7`）、下载到控制器、**修改IP地址（含端口）** |
| `Kine-X 调试` | 下载并运行、运行脚本、停止脚本、打开实时曲线、显示控制器信息、执行设备命令、刷新状态面板 |

> 「调试」下为**临时集合**，待定稿。

- **连接控制器**：分两步输入 **IP → 端口**，各自就地校验；任一步取消即中止（**不猜地址**、不静默回退）。
  输入过的 IP / 端口会记住，作为下次的默认值；设置项 `kine-x.host` / `kine-x.debugPort` 仍是初始默认值，
  也是调试器（DAP）的缺省。
- **同步**（`kine-x.sync`）：把控制器已保存的脚本**拉取**到工作区 `controller-sync/`（方向：控制器 → 本地）。
  缺 `d6`（板端未升级）或无工作区时**明确提示并中止**，不伪装；逐文件报告成功/失败。
  > 旧命令 `kine-x.sync.local` 保留为同一实现的别名（旧键位不失效）；「下载」才是本地 → 控制器方向。
- **重启控制器**（`kine-x.restart`，控制器需声明 `d7`）：模态确认后发送 `sys.restart`，板端先安全去使能、
  再经 systemd 重启 `kine-x.service`；插件随即自动重连（每 1.5s 重试，最长 20s）。
  控制器未声明 `d7`（板端旧固件或 `DEBUG_RESTART_CMD` 置空）时**明确拒绝**，菜单项置灰。
- **修改IP地址**（`kine-x.ip.set`）：打开与「连接控制器」相同的表单（**IP + 端口** + 就地校验），
  按钮为「保存」；保存写入设置 `kine-x.host` / `kine-x.debugPort`，作为后续连接与调试器的默认地址（**不立刻连接**）。

### 状态栏

- **左区**：`Kine-X v<插件版本>`（版本号取自 package.json，随 VSIX 更新；点击打开控制器信息）+ 运行概要（引擎 / 轴数 / 脚本状态；内容全部来自事件，**不轮询**）。
- **右区（固定最右）**：连接状态。连接成功显示「**已连接 `<ip>:<port>`**」，点击查看控制器信息。

## 设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| `kine-x.host` | `192.168.1.11` | 调试通道地址（控制器**业务网 IP**）；可用 **修改IP地址** 命令改写 |
| `kine-x.debugPort` | `5000` | 调试通道端口（对应控制器 `app.conf` 的 `DEBUG_PORT`） |
| `kine-x.token` | 空 | 可选鉴权 token（连接首帧校验）；留空不鉴权 |
| `kine-x.engine` | `basic` | 脚本引擎（`basic` / `lua`）；同一时刻只能加载一种 |
| `kine-x.sshForward` | `false` | 远程时提示生成 `ssh -L` 端口转发命令 |
| `kine-x.subscribeHz` | `20` | 状态订阅频率（Hz），越高界面越新但更费带宽 |
| `kine-x.axisRefreshHz` | `10` | **轴状态面板**界面刷新率（Hz，2~20）。订阅不变，面板按此频率增量重绘；数字跳动晃眼时调低，需要更跟手调高 |
| `kine-x.modbusRefreshHz` | `10` | **Modbus 寄存器面板**界面刷新率（Hz，2~20），同上；两个面板可分别调 |
| `kine-x.autoReconnect` | `true` | 意外断线后自动重连（指数退避 2/5/10/20/30s）；主动断开/调试交接不触发 |
| `kine-x.showRawProtocol` | `false` | 在「Kine-X 原始报文」输出栏打印 JSON-Lines，排查协议问题 |
| `kine-x.requestTimeoutMs` | `5000` | 单条 RPC 请求超时（毫秒） |

> **同网段直连（默认用法）**：调试口是**板端服务端**、随 `kine-x.service` **开机自启**并绑**业务网卡**，
> PC 上直接填 `192.168.1.11:5000` 即可。插件（VSCodium 扩展）**只装在 PC 上**，板端不跑 VSCodium。
> **跨网段**：控制器与 PC 不同网段时，配置 `ssh -N -L 5000:<控制器IP>:5000 user@控制器IP`，
> 再把连接目标设为 `127.0.0.1:5000`。开启 `kine-x.sshForward` 后，连接非回环地址时会**按输入的目标**
> 生成命令并复制到剪贴板（见 `docs/planA/13` §4.5）。

## 调试（DAP）

在 `.vscode/launch.json` 添加配置（或用代码片段 **Kine-X: 启动调试**）：

```json
{
  "type": "kine-x",
  "request": "launch",
  "name": "Kine-X 控制器调试",
  "host": "192.168.1.11",
  "port": 5000,
  "engine": "basic",
  "program": "${workspaceFolder}/demo.bas",
  "stopOnEntry": true,
  "waitBus": true,
  "maxSteps": 5000000,
  "trace": false
}
```

| 字段 | 对应控制器 | 说明 |
|------|------------|------|
| `host` / `port` / `token` | 调试通道 | 覆盖上面的设置项 |
| `engine` | —（调试口语言由 `DEBUG_SCRIPT_DIR` 现有脚本绑定） | 留空按 `program` 扩展名推断（D-03）；与控制器已绑定语言冲突时明确报 `ENGINE_MISMATCH` |
| `program` | — | 要运行的脚本；留空用当前打开文件 |
| `stopOnEntry` | — | 启动后停在入口，便于预置变量 |
| `waitBus` | `SCRIPT_WAIT_BUS` | 运行前等待总线就绪 |
| `maxSteps` | `SCRIPT_MAX_STEPS` | 步数预算 |
| `trace` | `SCRIPT_TRACE` | 跟踪打印 |

**断点 / 单步 / 变量**：在编辑器行号左侧设断点（BASIC 在语句边界停、Lua 在行级 hook 停）；命中后 **Variables** 面板查看/修改变量，
**Debug Console** 可执行表达式或设备命令（REPL）。快捷键与常规调试一致（F5 / F10 / Shift+F5）。

> **单客户端交接（v0.7.0）**：控制器调试口只服务一个客户端。启动调试会话时插件会**主动断开主连接**
> 让位给 DAP，会话结束后自动连回并恢复订阅/面板；调试期间手动「连接」会被拒绝（避免把调试器踢下线）。
>
> 断点语义为**会话级行号集合**：每次 `setBreakpoints` 会**全量替换**（先清空再逐行登记）。
> 协议只有行级单步，故 `next` / `stepIn` / `stepOut` **三者为同一语义**。

## 编辑体验（v0.8.0 完善）

- **补全**：命令名来自 `data/commands.json`（由控制器 `command_table.h` 生成，改表必须重跑 `gen-commands.mjs`）。
  Lua 下按签名插入带参数占位的片段（`MOVEABS(${1:p}, …)`），BASIC 直插命令名；组内常用命令排前。
- **Hover**：光标停在命令名上显示签名 + 一句话说明 + 分组（`kDocs` 单一事实来源）。
- **签名帮助**：输入 `(`、`,` 自动提示参数并高亮当前实参（`ww.call("NAME", …)` 也识别）。
- **语法高亮**：命令名表由生成器**注入**两份 TextMate 语法，与命令表永远一致（新增 `TICKS` 等自动生效）。
- **代码片段**：`include` / `moveabs`（异步）/ `en` / `ticks` / `server`（协作式 TCP 骨架）/ `while` 等。

## 状态面板、控制器文件与实时曲线

- **控制器文件**（侧边栏「控制器文件」**原生列表视图**，`kine-x.files`）：列出控制器 `DEBUG_SCRIPT_DIR` 里的脚本
  （语言图标：Basic 绿 / Lua 蓝 / 其他灰；右侧显示语言 + 大小 + **一致性标识**）。操作：
  - **点击行 / 行内「拉取到工作区」** → 拉取到工作区 `controller-sync/`；
  - **行内/右键「设为主文件（开机运行）」**（需控制器 `d8`）→ ★ 标记该文件为开机自动运行的主文件
    （`boot.set`，**下次启动生效**；设置后可直接点提示里的「重启控制器」立即应用）；
    主文件行可用「取消主文件」；主文件被删后列表顶部会明示"主文件不可用"；
  - **行内/右键「删除控制器文件」** → 模态确认后 `file.del`（**删空目录会让脚本语言回到「自动」**；
    删除主文件时确认框会加重提示）；
  - **视图标题栏**：刷新、全部拉取（=「同步」同实现）。
  - **一致性标识**（v0.8.4，需控制器 `file.list` 带 `hash`——旧固件显示"未比较"）：
    控制器文件内容（FNV-1a 64）与本地 `controller-sync/<同名文件>` 逐一比对——
    **一致**（哈希相同）/ **不一致**（本地有改动或控制器侧已更新，重新拉取会覆盖本地副本）/
    **本地无副本**（点击本行或「同步」拉取后可比对）/ **未比较**（无工作区、读失败或旧固件）。
  未连接 / 缺 `d6` / 拉取失败 / 目录为空都以**占位行**明示原因，不伪装成空列表。
  文件只在「下载带文件名且编译成功」时落盘——**空列表 = 还没有成功下载过脚本**；
  这份列表同时决定调试口语言（空 = 两种都可下载，首次落盘绑定）。
- **轴状态**：编辑器区 Webview 面板（菜单「工具 → 轴状态」）；顶部有**最后更新时间**与「**暂停刷新**」按钮
  （冻结界面读数/复制，数据仍在后台更新），刷新率见 `kine-x.axisRefreshHz`（默认 10Hz，增量渲染不闪烁）；
  表格列：轴 / 总线 / 使能 / 空闲 / 报警 / **指令位置 DPOS（4 位小数）** / **反馈位置 MPOS（4 位小数）** / AL 状态 / 错误码；
  调试行含「**脉冲当量**」输入与「应用当量」（`UNITS`，inc/mm；显示当前生效值，未设置显示「未设置」；运动中不可改）；
  未收到的项显示「—」；AL 状态列按位表解码出名称，位表之外被置位的位置会标注「(位N未知)」，不臆造含义。
- **Modbus 寄存器**：独立面板（菜单「工具 → Modbus」），4x 区 256 个寄存器分 16 组 × 16（折叠分组，展开状态自动保留）；
  顶部同样有**最后更新时间**与「**暂停刷新**」，刷新率见 `kine-x.modbusRefreshHz`（默认 10Hz，增量渲染）；
  能区分「全为 0」与「尚无数据」。
- **实时曲线**：`Kine-X 调试: 打开实时曲线`；选择轴，绘制位置曲线。**缺采样补空**（断线不补 0、不插值），
  断线会清空窗口，避免把旧数据当成当前数据。

> 轴面板**首次可见**时取一次快照（`axis.snapshot`），此后全靠事件推送；手动 `刷新状态面板`
> 会重新对齐订阅并重取快照。

## 协议与「降级不伪装」

插件启动即读取控制器能力声明（`sys.info.caps`），据此决定 UI：

| 能力位 | 含义 | 缺失时的行为 |
|--------|------|--------------|
| `d1` / `d2` | 基础 RPC / 脚本下载运行 | 连接或基本功能不可用，明确报错 |
| `d3` | 状态订阅（面板/曲线） | 面板明示「订阅不可用」，不静默空表 |
| `d4` | 热更新（运行中换脚本） | 提示「请先停止再下载」，不假装成功 |
| `d5` | 断点/单步/暂停 | 断点回 `verified:false` + 说明；单步/暂停报「不支持」 |

**原则**：控制器不具备的能力，插件一律**明示「不支持」**，绝不用假象掩盖。

## 常见问题（FAQ）

**Q：连不上控制器？**
先确认连接弹窗里输入的 IP / 端口与控制器 `DEBUG_PORT` 一致（设置项 `kine-x.host` / `kine-x.debugPort`
只是默认值）；远程需做端口转发；查看输出面板「Kine-X 调试」的报错原因。

**Q：面板一直是「等待数据」？**
控制器可能未声明 `d3`（订阅能力），或脚本未运行、总线未就绪。打开 `kine-x.showRawProtocol`
看是否有 `axis` / `bus` / `mb` 事件推送。

**Q：下载脚本时提示「请先停止再下载」？**
控制器未声明 `d4`（热更新）。先运行 `Kine-X 调试: 停止脚本` 再下载，或在控制器侧开启该能力。

**Q：下载时报 `ENGINE_MISMATCH`/「控制器当前脚本语言为 …」？**
控制器调试口的语言**由脚本目录里现有脚本决定**（不是配置项）：`sys.info.engine` 报
`basic`/`lua`（已绑定）/`auto`（空目录，两种语言都可以下载，第一次成功下载后绑定）/`mixed`
（目录同时有 `.bas` 与 `.lua`，编译被拒）。
- 显示「自动」时：直接下载 `.bas` 或 `.lua` 都可以，成功即绑定该语言；
- 显示 `basic`/`lua` 时：请用同语言脚本；想换语言，先删掉控制器里另一种/当前的脚本文件
  （「控制器文件」列表可删）——**目录为空后自动回到「自动」，即可下载另一种语言**；
- 显示「混合」时：在文件列表里删掉其中一种语言的脚本再下载。
> `config/app.conf` 的 `SCRIPT_ENGINE` 只用于开机自动脚本（`SCRIPT_ENABLE=1`），不影响调试口。
> `basic`/`lua` 绑定时插件会**本地前置拦截**并给出上述处理办法，不发必然被拒的编译请求。

**Q：同步提示「控制器引擎未知」/「控制器未声明 d6」？**
「同步」/「全部拉取」= 把控制器文件拉回工作区：未连接/未取到 `sys.info` 时先连接；板上固件较旧未声明
`d6`（文件管理）时，文件列表显示「需升级板端」占位行，不伪装空列表。

**Q：多个脚本文件怎么组织？哪个会开机运行？**
控制器开机只运行**一个主文件**（在「控制器文件」列表中带 ★ 的那个，控制器侧 `d8`/`.boot` 清单）。
其它文件由主文件调用：在**主文件**里独占一行写 `INCLUDE "sub.bas"`（BASIC）或 `include("sub.lua")`（Lua），
控制器在编译前把它们展开合并（子程序之间用全局变量通信）。规则：只能引用同语言、同目录下的纯文件名；
嵌套 ≤ 8 层、循环会明确报错；错误行号按合并后的源码计。没设主文件时回退到控制器配置的 `SCRIPT_FILE`。

**Q：设了主文件但没生效？**
主文件设置**下次启动生效**——设置成功后点提示里的「重启控制器」立即应用（或手动重启板端服务）。
若看到"主文件不可用"占位行，说明清单引用的文件已被删除或与目录语言冲突，重新指定即可。

**Q：点「重启控制器」没反应 / 菜单置灰？**
重启需要控制器声明 `d7`（`sys.info.caps` 含 `d7`，即板端 `DEBUG_RESTART_CMD` 非空）。旧固件需升级；
置灰即控制器未声明该能力（不伪装可用）。重启会中断脚本/调试会话/电机任务（驱动器先安全去使能），
确认后插件会自动重连（每 1.5s，最长 20s；超时会提示手动连接）。

**Q：文件列表显示「删除控制器文件」会有什么影响？**
删除的是控制器 `DEBUG_SCRIPT_DIR` 里的脚本（本地工作区副本不受影响）。若删到目录为空，
调试口脚本语言会回到「**自动**」——`.bas`/`.lua` 都可再下载；若目录内只剩另一种语言，
绑定也会随之切换。删除前有模态确认。

**Q：连接突然掉了 / 控制器重启后？**
插件默认**自动重连**（指数退避 2/5/10/20/30s，状态栏显示「重连中(第N次)」），成功后自动恢复 `sys.info`、日志与面板订阅；
不需要可在设置里关掉 `kine-x.autoReconnect`。调试会话结束后也会自动连回（会话期间连接由调试器占用）。

**Q：断点不生效 / 提示不支持？**
控制器未声明 `d5`（断点/单步需引擎调试钩子；v0.8.0 起 BASIC 与 Lua 均实装）。此时仍可正常运行与停止、查变量。

**Q：`lua` 引擎配 `.bas` 被拦截？**
这是刻意的一致性校验（`engine_rule`）：同一时刻只能加载一种语言。改 `kine-x.engine` 或用匹配扩展名。

**Q：中文乱码？**
首版为中文界面；若输出乱码，检查控制器输出编码与终端编码一致。
