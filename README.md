# ZMC 运动控制综合项目（EtherCAT + Socket + Modbus HMI + 485 称重 + 机器人 Socket）

> 平台：正运动 ZMC3xx/4xx 控制器，ZBasic 脚本
> 主程序：`EtherCAT_SocketServer.bas`（ZDevelop 下载到控制器运行）
>
> ⚠ **新控制器（Kine-X：鲁班猫2 + IgH EtherCAT）上的等价实现**：`EtherCAT_SocketServer.lua`
> （Lua 5.4，2026-09-26 移植）——**IP / 端口 / 报文格式 / Modbus 寄存器映射全部不变**，
> 上位机与 IT7000 触摸屏无需任何修改；由插件「控制器文件」设为主文件后开机自动运行。
> 新旧差异（单线程协作步进、异步定位、Lua 侧 TICKS 计时、502 需 CAP_NET_BIND_SERVICE 等）
> 见该文件头部注释。

## 一、项目简介

本项目基于正运动 ZMC 控制器，把**总线运动控制**、**远程 Socket 控制**、**触摸屏 Modbus 通讯**、**485 数字称重采集**、**机器人 Socket 通讯**五套功能整合进同一个 ZBasic 程序，上电自动运行，具备断线重连与任务看门狗自恢复能力。

本项目为**单轴应用**：总线上只有 1 个轴，轴号固定为 **0**，所有运动命令与位置寄存器均针对轴 0。程序内已按单轴直写（不含多轴循环），命令中的 axis 字段仅为兼容保留、取值被忽略。

五套功能分别跑在 5 个独立任务中，互不阻塞：

| 任务 | 入口 | 职责 |
|------|------|------|
| 任务0 | 主程序 | EtherCAT 总线初始化、SDO 配置、输入口调试、看门狗 |
| 任务1 | `socket_task` | TCP 服务端（端口 4321），ASCII 命令收发 + 心跳 |
| 任务2 | `modbus_task` | Modbus-TCP 从站（502），汇川 IT7000 触摸屏轮询 |
| 任务3 | `scale_task` | Modbus-TCP 客户端，经网关采集 485 称重模块 |
| 任务4 | `robot_task` | TCP 客户端，连机器人（192.168.1.221:4320），状态监控 + 命令透传 |

## 二、网络拓扑

```
┌──────────────────┐   EtherCAT    ┌──────────────┐
│  ZMC 控制器      │───────────────│  伺服驱动器  │
│  192.168.1.11    │               └──────────────┘
│                  │
│  网口0  :4321 TCP_SERVER(ECUSTOM 10)  ←── PC 上位机（ASCII 命令）
│  网口    :502  Modbus-TCP 从站(ETH)   ←── 汇川 IT7000 触摸屏（Modbus 主站）
│  网口    :500  在线调试(ETH)          ←── ZDevelop 电脑 192.168.1.22
│  网口1  :客户端(ECUSTOM 11)           ──→ TAS-LAN-869 网关 192.168.1.80:10123
│         TCP_CLIENT                    ──→ 机器人 192.168.1.221:4320（机器人做 TCP 服务端）
└──────────────────┘                    │ 纯透传(TCP Server)
                                        ↓ RS485（9600,8,N,1）
                                  数字称重模块（站号 1）
```

### 端口 / 通道占用对照（排查网络问题时先看这张表）

| 用途 | 端口 | 通道 | 由谁建立 | 备注 |
|------|------|------|----------|------|
| PC 上位机 ASCII 命令 | 4321 | **ECUSTOM 10** | 程序 `OPEN #10,"TCP_SERVER"` | 服务端常驻监听 |
| 触摸屏 Modbus-TCP 从站 | 502 | **ETH** | 固件自动监听 | 无需 `OPEN`，控制器为从站 |
| ZDevelop 在线调试 | 500 | **ETH** | ZDevelop 电脑发起 | 该电脑即 `192.168.1.22` |
| 称重网关客户端 | →80:10123 | **ECUSTOM 11** | 程序 `OPEN #11,"TCP_CLIENT"` | 控制器为客户端 |
| 机器人 Socket | →221:4320 | 待腾出 | 程序 `OPEN #ROBOT_CH,"TCP_CLIENT"` | 通道不够，见第八节 |

> ★**ETH 通道 ≠ ECUSTOM 通道**：`ETH` 通道是控制器自身网口协议栈（供 **ZDevelop 在线(500)** 与 **Modbus-TCP 从站(502)** 使用，**不能用 `OPEN` 当自定义 TCP 用**，也不能配置增减）；`ECUSTOM` 通道才是程序 `OPEN` 用的自定义网口（本机仅 2 个：10/11）。
> ★**排查纪律**：看到 `PORT_TARGET(n)` 里有对端 IP 时，先确认该通道是"ETH 在线"还是"ECUSTOM 业务"，不要把 **ZDevelop 在线连接**误认为外部客户端连接（曾把 `192.168.1.22:64762`（ZDevelop 在线电脑）误判为"设备连上了 502"）。

## 三、功能清单

### 1. EtherCAT 总线初始化（任务0）

- `slot_scan(0)` 扫描总线，未扫到设备自动 2s 重试。
- 自动映射轴号 `AXIS_ADDRESS`（本项目单轴，仅使用轴号 0），`ATYPE=65`，`units=PULSE_EQUIV(14043.41)`（**1 unit = 1mm**）。
- 每轴独立分组 `disable_group`，设置 `SPEED/ACCEL/DECEL` 默认值。
- `SLOT_START(0)` 启动总线，依次清除驱动器错误（控制字 128→6→15）与控制器错误 `datum(0)`。
- 全部轴使能并置位使能总开关 `wdog`。
- **输入口调试**（保留原程序）：`in0~in7`、`in22`、`in23` 打印设备/IO/AD-DA 信息、`?*ETHERCAT`、点动、急停、SDO 写入、重扫总线、停止总线。

### 2. TCP Socket 服务端（任务1，端口 4321）

- `OPEN #10,"TCP_SERVER",4321`，在总线初始化**之前**开启，总线重试期间端口始终在线。
- 客户端断开后通道保持监听，可直接重连。
- 命令结束符：`;` 或 回车/换行，或发送后空闲 200ms 自动按完整命令执行。
- 服务端心跳：连接期间每 2s 主动发 `beat/n`，客户端超时收不到即判失联。
- 应答统一以**字面 `/n`**（两个字符，不是换行）结尾，上位机按报文/关键字读，**不能用 readline**。

### 3. Modbus-TCP 从站（任务2，端口 502）

- 控制器 = Modbus-TCP 从站（服务端），内置网口固件自动监听 502，无需 `OPEN`。
- 汇川 IT7000 触摸屏 = 主站（客户端），站号 1（`ADDRESS = 1`）。
- 提供轴状态、位置、轴数读取，以及使能/急停/运动/点动等远程操作。
- 32 位数据字序：**低字在前**（低字在低地址；2026-09-26 触摸屏实测定案）；屏端字序项须与此一致，
  否则位置非零时显示 `####` 或极大值（此前"1234/高字在前"的记载为误，已废弃）。

### 4. 485 数字称重采集（任务3）

- 链路：控制器（**Modbus-RTU 主站**，TCP 客户端）→ TAS-LAN-869 网关（192.168.1.80:10123，TCP Server，**纯透传、未开启 Modbus-TCP/RTU 转换**）→ RS485 称重模块（站号 1，9600 8N1）。
- 网口上跑的就是 485 总线上的**原始 Modbus-RTU 字节**（站号 + 功能码 + 数据 + CRC16，低字节在前），**无 MBAP 头**；必须按 RTU 组帧，**不能**按 Modbus-TCP 组帧。
- 周期轮询实时重量 + 内码；支持去皮 / 取消去皮 / 零点校准 / 清除错误计数 / 改比例系数 / 改站号。
- 具备**粘包分包重组**（按 RTU 帧长切帧，帧头非法/CRC 错时丢首字节重同步）、超时计数、断线重连。
- ★**CRC 字节序（实测定案）**：内置 `CRC16()` 返回值按"发送顺序"打包（高 8 位 = 帧内**先发**的低字节）。组帧必须 `SCALE_TX(6)=crc\256`、`SCALE_TX(7)=crc AND $FF`；写反则模块 CRC 校验不过、**静默不应答**，现象就是"应答超时/缓冲内 0 字节"。

### 5. 机器人 Socket 通讯（任务4）

- 链路：控制器（**TCP 客户端**）→ 机器人（**TCP 服务端**，`192.168.1.221:4320`）。与称重链路方向相反，控制器是主动方。
- **开机延迟等待**：上电后先等 `ROBOT_BOOT_WAIT`（默认 20s）让机器人启动完毕，期间**不发起连接**；之后按 `ROBOT_RECONN_MS`（默认 5s）间隔重连，链路建立后自动转入状态监控。
- **状态监控（轮询表）**：连上后每 `ROBOT_POLL_MS`（默认 500ms）从监控指令表 `ROBOT_KEYTAB` **按序取一条**发出（末尾补 `LF`，即 `\n`），应答按 `LF/CR/;` 拆包缓存到 `ROBOT_MSG`，解析后存入 `robot_st(序号)`。12 条监控量刷完一轮约 6s：

  | 序号 | 监控指令 | 含义 | 序号 | 监控指令 | 含义 |
  |---|---|---|---|---|---|
  | 0 | `motor_on_state` | 电机上电状态 | 6 | `collision_state` | 碰撞检测状态 |
  | 1 | `robot_running_state` | 程序运行状态 | 7 | `task_state` | 运行任务状态 |
  | 2 | `estop_state` | 急停状态 | 8 | `cart_pos` | 笛卡尔位置 |
  | 3 | `operating_mode` | 工作模式 | 9 | `jnt_pos` | 关节位置 |
  | 4 | `home_state` | Home 输出状态 | 10 | `jnt_vel` | 关节速度 |
  | 5 | `fault_state` | 故障状态 | 11 | `jnt_trq` | 关节力矩 |

- **控制机器人**：两条路都通——①PC 侧短命令（`RON;` 上电、`ROFF;` 下电、`RSTART;`/`RSTOP;` 启停、`RMAIN;` 回 main、`RCLEAR;` 清报警、`RAUTO;`/`RMAN;` 自动/手动、`RDRAG;`/`RUDRAG;` 拖动开关、`RLIST;`/`RCUR;` 工程列表/当前工程、`RLOAD,<工程名>;` 切换工程）；②`RCMD,<任意内容>;` 通用透传。链路未连接时一律应答 `ERR:ROBOT`（**绝不盲发**）。
- **应答格式兼容**：①带字段名（JSON/CSV：先在报文里找指令名，再取其后的数值）②一问一答纯值（整条报文就是数值，如 `1`）；`true`/`false` 亦识别。
- 连接纪律与称重任务一致：**必须先确认 `PORT_STATUS(12)=1` 才收发**，未连接时只按间隔重试 `OPEN`。
- ★**协议适配区**（4 处）：`ROBOT_KEYTAB`（监控指令表）、`ROBOT_CTLTAB`（控制指令表）、`ROBOT_ALARM_KEY`（报警关键字，现为 `fault`）、`robot_num()`（数值提取规则）。

**协议测试方法（机器人回复未知时）**：把 `ROBOT_DBG` 置 1、下载程序，上电约 20s 连上机器人后，控制器会按监控表轮询并**逐条打印**：

```
机器人:★TX(监控0):motor_on_state            ← 发出的指令(末尾自动补LF)
机器人:★RX 12字节 HEX: 31 0D 0A ...          ← 原始字节(HEX,可看到CR/LF等不可见字符)
机器人:★报文[监控条0]=1  (解析值1 有效1)     ← 拆包后的可读报文与解析结果
```

想逐条对号入座时，PC 发 `RMON,<序号>;`（0~11）单步触发某一条；发任意原始指令用 `RCMD,<内容>;`。测试完把 `ROBOT_DBG` 改回 0。

## 五、触摸屏 Modbus 寄存器映射

### 输入区（触摸屏 → 控制器）

| 寄存器 | 类型 | 说明 |
|--------|------|------|
| 4x0 | int16 | HMI 数据 1 → `hmi_val(0)`，置 `hmi_flag(0)`，`hmi_cnt(0)` 计数 |
| 4x1/4x2 | float32 | HMI 数据 2 → `hmi_val(1)`，置 `hmi_flag(1)`，`hmi_cnt(1)` 计数 |

### 回写与读区（控制器 → 触摸屏）

| 寄存器 | 类型 | 说明 |
|--------|------|------|
| 4x4 | int16 | 4x0 原值回写显示 |
| 4x5/4x6 | float32 | 4x1 原值回写显示 |
| 4x3 | int16 | 状态字 bit0=运动中 bit1=报警 bit2=已使能 bit3=总线正常 |
| 4x9 | int16 | 总线轴数（本项目恒为 1） |
| 4x10/4x11 | float32 | 轴 0 当前位置 MPOS(0)（mm） |
| 4x12/4x13 | float32 | 轴 0 指令位置 DPOS(0)（mm） |

### 命令与运动区（触摸屏 → 控制器）

| 寄存器 | 类型 | 说明 |
|--------|------|------|
| 4x60 | int16 | 命令字 bit0=使能 bit1=去使能 bit2=急停 bit3=重扫总线（上升沿） |
| 4x61 | int16 | 目标轴号（单轴，固定填 0） |
| 4x62/4x63 | float32 | 目标位置（mm） |
| 4x64 | int16 | 定位速度。屏端按 **1 位小数**输入（存值=显示值×10），程序 ÷10 还原为 mm/s；上限 **3276.7** |
| 4x65 | int16 | 模式 0=绝对 MOVEABS，1=相对 MOVE |
| 4x66 | int16 | 运动触发（0→1 上升沿执行一次，需先置 0 再置 1） |
| 4x67 | int16 | 点动使能 1=点动 |
| 4x68 | int16 | 点动方向 1=正 -1=负 |
| 4x69 | int16 | 点动速度。同 4x64：屏端 1 位小数×10 存储，程序 ÷10 还原；上限 **3276.7** |

### 称重区（4x120~4x135）

| 寄存器 | 类型 | 说明 |
|--------|------|------|
| 4x120 | int16 | 称重状态字 bit0=通讯正常 bit1=数据有效 bit2=出错 bit3=已连接 bit4=执行中 bit5=成功 bit6=失败 |
| 4x121 | int16 | 错误计数（超时/异常应答累计） |
| 4x122/4x123 | float32 | 重量（显示单位，= 原始值 / 比例系数） |
| 4x124/4x125 | float32 | 原始重量（模块内部计数，有符号） |
| 4x126/4x127 | float32 | 内码（AD 码，诊断用，无符号） |
| 4x128/4x129 | float32 | 零点内码（零点校准瞬间记录） |
| 4x130 | int16 | 写：称重模块站号（1~247，默认 1） |
| 4x131 | int16 | 写：轮询周期（20~5000ms，默认 200） |
| 4x132/4x133 | float32 | 写：重量比例系数（默认 100.0，即模块 10000 → 显示 100.00） |
| 4x134 | int16 | 写：命令字 1=去皮 2=取消去皮 3=零点校准 4=清错误（上升沿，执行后请置 0） |
| 4x135 | int16 | 命令结果 0=空闲 1=执行中 2=成功 3=失败 |

### 机器人区（4x140~4x149）

| 地址 | 类型 | 说明 |
|------|------|------|
| 4x140 | int16 | 机器人状态字 bit0=通道已连接 bit1=通讯正常 bit2=机器人报警 bit3=有命令待发 bit4=监控数据已建立（至少完整轮询过一轮） |
| 4x141 | int16 | 机器人错误计数（应答超时等累计） |
| 4x142 | int16 | 机器人累计收到报文数（诊断用） |
| 4x143 | int16 | 电机上电状态 `motor_on_state`（1=已上电） |
| 4x144 | int16 | 程序运行状态 `robot_running_state`（1=运行中） |
| 4x145 | int16 | 急停状态 `estop_state`（1=急停） |
| 4x146 | int16 | 工作模式 `operating_mode`（取值按机器人协议定义） |
| 4x147 | int16 | 故障状态 `fault_state`（0=正常） |
| 4x148 | int16 | 碰撞检测 `collision_state`（1=碰撞） |
| 4x149 | int16 | 运行任务状态 `task_state` |

> 4x143~4x149 由监控指令表轮询逐条刷新，**刷完一轮约 6s**（12 条 × 500ms），屏上数值可能滞后数秒；位置/速度/力矩是多关节数组，未上屏，可用 `RSTA;` 或看控制器打印的报文。
> 机器人控制走 PC 侧短命令或 `RCMD` 透传；字符串类命令（`load_prog:` + 工程名）不适合直接放 Modbus 寄存器，故未做触摸屏控制字。

## 六、称重网关配置清单（上线前逐项确认）

TAS-LAN-869 网关需配置：

1. 工作模式：**TCP Server**，监听端口 **10123**。
2. 串口参数：**9600, 8, N, 1**（与称重模块一致）。
3. **关闭**"Modbus TCP 与 Modbus RTU 转换"（本项目走**纯透传**，控制器自己组 Modbus-RTU 帧；开启转换反而会让网口端按 MBAP 解析而错帧）。
4. **关闭**注册包、**关闭**业务心跳包、**关闭** Modbus 轮询采集（这些会导致粘包/异常帧）。
5. 若为省事也可改用 502 端口 + **开启**转换，此时控制器须改发 Modbus-TCP(MBAP) 帧并改用 `MODBUSM_*` 主站指令（本项目未采用）。

称重模块侧：

- 站号 1、波特率 9600、8N1、写保护寄存器 `0x0017`（**1=关闭**）。
- 去皮 `0x0015`，零点校准 `0x0016=1`，恢复出厂 `0x0016=9`（慎用，会清标定）。
- 32 位寄存器**低字在前**：`值 = 高字*65536 + 低字`。

## 七、部署与运行

1. ZDevelop 打开 `EtherCAT_SocketServer.bas`，确认控制器 IP（默认 192.168.1.11）与端口。
2. 用在线命令 `?*PORT` 确认自定义网口通道号（**认准 `ECUSTOM` 且状态为 0/未占用**；串口 0/1 的状态恒为 1，别选）。本项目已固定：`COM_PORT=10`（4321 服务端）、`SCALE_CH=11`（称重网关客户端）。★**本控制器实测只有 2 个自定义网口**（端口表 `Port:10-ECUSTOM` / `Port:11-ECUSTOM`，与型号参数 `max_ethcustom=2` 一致），`PORT_STATUS` 最大下标也只有 11（写 12 → 任务4 直接 `error 2024: Array index over max` 停机）→ 机器人链路**没有第三条通道**，必须先用第八节"通道不够用"方案腾出/替换一条链路，再改 `ROBOT_CH` 与 `PORT_MAX`。
3. 配置网关（见第六节），确认触摸屏 Modbus 站号 = 1。
4. **下载程序到控制器**（FLASH），并勾选"下载后自动运行任务 0"。
5. 上电后等待 5~10 秒（`wa 1000` + 扫总线），再验证：
   - `?ATYPE(0)`、`?UNITS(0)` 或直接连 4321 测试命令；
   - `?*TASK` 查看任务 0/1/2/3 是否均为 RUN。
6. PC 端用 TCP 工具连接 `192.168.1.11:4321` 发 `WSTA;` 验证称重链路。
7. **正式运行前确认调试开关已关**：程序顶部 `DBG=0`、称重区 `SCALE_DBG=0`（默认已置 0），避免控制台刷屏；排查时临时改 1 再下载。
8. 触摸屏速度元件（`4x64` / `4x69`）设为 **int16 + 小数位数 1**，输入上限建议设为 **3276.7**（见第八节速度上限说明）。
9. 机器人侧确认：`192.168.1.221:4320` 已开放 TCP 服务端，且控制器可路由到该 IP（PC 上 `ping 192.168.1.221`）。上电后控制器需先等约 20s 才发起连接，属正常现象。

> 注意：`ATYPE/UNITS/SPEED` 等轴参数为 **RAM 型**，控制器断电重启会全部丢失回默认值，唯一恢复方式是重新"下载程序到控制器"并勾选"下载后自动运行任务 0"，由程序初始化段自动重设。

## 八、关键注意事项

- **TICKS 是倒数计数器**：计耗时必须 `t0 = TICKS` → `t0 - TICKS`，写反则超时判断永不触发。
- **`PRINT #` 不附加换行**：一次 `PRINT #` = 一个 TCP 包，上位机须按报文/关键字读取。
- **单位换算只做一次**：`units(num) = PULSE_EQUIV` 后 1 unit = 1mm，`MOVEABS/MOVE/VMOVE/SPEED/ACCEL/DECEL` 参数直接用 mm 值，MPOS/DPOS 返回值即 mm。**禁止再乘/除 PULSE_EQUIV**。
- **ZBasic 块式 if 必须配对 `endif`**，禁止单行 `if ... then ... endif` 混写。
- **主程序(任务0)不要用 `i` 当循环变量**：子程序里的 `LOCAL i` 与主程序私有的 `i` 同名时，控制器启动会打印 `Local and Private name:I is same.`，两者可能共用同一存储 → 多任务并发时循环变量互相踩（称重移帧/出队、输入口调试打印都会偶发错乱）。主程序已统一改名为 `ii`，`i` 只出现在声明了 `LOCAL` 的子程序内部。
- **称重 CRC 字节序**：内置 `CRC16()` 返回值按发送顺序打包，组帧必须 `crc\256` 在前、`crc AND $FF` 在后；写反 → 模块静默不应答（表现为超时）。程序内 `SCALE_DBG=1` 时的 CRC 自检是回归护栏。
- 新增任务后，务必在主程序看门狗里补上 `PROC_STATUS` 检查，保证异常停止后自动拉起。
- **HMI 速度寄存器按 1 位小数存储**：屏端 `4x64` / `4x69` 必须保持"小数位数 = 1"（存值 = 显示值 × 10），程序内 ÷10 还原为 mm/s；屏端改成 0 位小数会让速度再被除以 10（慢 10 倍）。
- **HMI 速度上限 3276.7 mm/s**（int16 上限 32767 ÷ 10）：屏端输入超限时 int16 会**回绕成负数**（如 40000 → -25536），程序内已把 `> MV_SPD_MAX` 或 `< 0` 一律按 `MV_SPD_MAX` 处理；建议屏端元件同时设输入上限做双保险。
- **机器人链路方向与称重相反**：机器人是**服务端**、控制器是**客户端**（`OPEN #ROBOT_CH,"TCP_CLIENT",4320,"192.168.1.221"`）；同样必须先 `PORT_STATUS(ROBOT_CH)=1` 才收发。
- **ZDevelop 在线(500) 与 502 从站是两条独立连接，不冲突但要分清**：在线调试占用一条 `ETH` 通道，Modbus-TCP 从站(502) 用另一条，二者可同时在线；`ECUSTOM 10/11`（4321 服务端 / 称重客户端）与它们无关。**排查网络前先确认"谁占着哪条通道"**（对照表见第二节），不要把在线连接误当成外部客户端连接。
- **判断触摸屏是否连上 502，只有两条可靠途径**：①`?*PORT` 看通道表（分清朝 `ETH` / `ECUSTOM`），再用 `?PORT_STATUS(n)` 看该通道是否被占用、`?PORT_TARGET(n)` 打印对端 IP，出现触摸屏 IP 即已连上；②**硬证据 = 在屏上改一下 `4x0` 的值**，`?hmi_cnt(0)` 应自增。★`hmi_cnt` 是"值变化计数"而**不是心跳**：屏上持续刷新同一个值不会让计数增长，**不能用"计数不动"判定掉线**。
- **屏上数值刷新异常时的快速排除法**：短暂断开 ZDevelop 在线，再看屏是否恢复正常，以排除"在线链路占 ETH 通道 / 与 502 从站相互干扰"；现场不会长期挂 ZDevelop，这个特性应提前掌握。
- **★通道下标不能超过 `PORT_MAX`**：`PORT_STATUS(通道号)` 下标越界会让**整个任务直接报错停机**（`error 2024 Array index over max`），程序已在 `robot_task` 开头加保护（越界则打印提示后空转，不影响其它任务）；`PORT_MAX` 必须按 `?*PORT` 实测值修改（本控制器实测最大下标 11）。
- **★"通道不够用"（本机现状）**：`?*PORT` 里只有标 `ECUSTOM` 的通道能 `OPEN`，实测本控制器**只有 2 个自定义网口**：`10`（PC 4321 服务端）、`11`（称重网关客户端），已被占满，机器人链路拿不到第三条通道。四条备选（按推荐度）：
  - **① 称重改接控制器自带 RS485（推荐）**：把称重模块/网关的 485 直接接到控制器串口（9600 8N1、Modbus-RTU 主站，可用 `SETCOM(...,14,...)` 串口 Modbus 主站模式），任务3 由 `OPEN #11,"TCP_CLIENT"` 改为串口收发 → 释放 `11` 给机器人（`ROBOT_CH=11`），上位机/触摸屏寄存器不变，且少一个网关、少一条以太网依赖。前提：现场能拉 485 线（9600 支持 1200m）。
  - **② 机器人链路移到 PC 上位机中转**：PC 同时连机器人 4320 与控制器 4321，PC 轮询机器人后把值下发到控制器新增命令（如 `RSET,<序号>,<值>;` 写入 4x140~4x149），`RSTA` 直接读寄存器；`RCMD` 由 PC 直接发给机器人。改动主要在 PC 侧（控制器侧命令与映射由本程序配合）。
  - **③ 控制器 RS232 加"串口转网口"透明模块**：模块设为 TCP Client 指向机器人 4320，控制器侧改用串口发同样的文本协议（链路状态只能靠超时/RX 判断，`PORT_STATUS(0/1)` 恒为 1 不可信）。纯控制器侧改动 + 一个模块 + 接线。
  - **④ 更换/升级控制器型号**（`max_ethcustom` 更大的型号）或向厂家确认是否有放宽该参数的固件；**不建议**让机器人当客户端去共用 PC 的 4321 通道——`PRINT #10` 是广播，机器人会收到发给 PC 的应答，协议必然串扰。
- **机器人开机延迟必须"取差值"实现**：任务内 `robot_boott = TICKS` 记录启动时刻，判断 `robot_boott - TICKS < ROBOT_BOOT_WAIT`；**不要**写成 `robot_boott = ROBOT_BOOT_WAIT`（TICKS 是倒数计数器，那样延迟会直接失效）。
- **`ROBOT_DBG` 现为 1（协议测试期）**：逐条打印收发报文（含 HEX 原始字节）+ 报文带监控序号；协议定案后必须改回 0，恢复正式运行的"仅报文变化才打印"。协议适配只需改 `ROBOT_KEYTAB`（监控指令表）/ `ROBOT_CTLTAB`（控制指令表）/ `ROBOT_ALARM_KEY`（报警关键字）/ `robot_num()`（数值提取）四处，连接与重连机制无需改动。
- **消息后缀是单字节 `LF`(`\n`)，不是 CRLF**：实测确定；发送处两处（透传/轮询）均只补 `10`。
- **`ROBOT_KEYTAB` 段数必须与 `ROBOT_MON_N` 一致**（现为 12）：增删监控量时两处必须同步，否则轮询会取到空指令或漏项。
- **报警判定依赖 5/2/6 号监控量**（`fault_state` / `estop_state` / `collision_state`）：若调整监控表顺序，必须同步修改 `robot_parse()` 里的报警汇总下标，否则报警会误判。
