# 2026-09-29 记忆（机器人 Modbus 直连 / 轴0位置控制 / 安全联锁）

## 机器人控制轴0位置（Modbus）
- 4x1080 = 目标（**int16 整数 mm**，负数补码；**值变化即触发**）；4x1082 = 同目标重触发（0→1 沿，需先写过 4x1080「armed」，控制器不自动回 0）。
- 4x1140 = 轴0状态：**收到位置立即置 0（已受理/执行中）→ 到位 2 / 失败 4**；到位/失败为瞬时结果（1s 保持后回 0）；触屏写 4x66 定位也走同一状态字。
- 定位用 `MOVEABS(...,wait=0)` 异步下发；速度/加减速=内核缺省（=地轨参数 4x71~73）。
- 机器人侧绑定：只写起始 1000、**个数 ≥83**（覆盖 1080~1082）；只读起始 1100、**个数 41**（覆盖 1140）；CDAB 低字在前。
- 现场状态：机器人写 1000~1008 正常；写 1080 曾不到达（机器人侧发送范围问题，待扩范围后复测）；触屏路径已验证可动。

## ★安全联锁（新，2026-09-29）
- 机器人 **急停（4x145 非 0）或故障（4x147 非 0）→ 轴0 强制去使能（DISABLE）**。
- 未复位期间**每秒复查、保持关闭**（防重新使能）；信号复位 → 联锁解除，**不自动使能**（需人工/屏幕重新使能）。
- 急停极性：脚本常量 `ROBOT_ESTOP_ACTIVE_HIGH`（默认 true=非 0 即急停；随机器人「急停触发电平类型」）。
- 日志：`[axis0] 安全联锁：机器人急停/故障信号（4x145=…, 4x147=…）→ 伺服去使能` / `安全联锁解除`。
- 自测：`port_script_selftest.lua` 增 4 条（复位未触发/4x145 触发/4x147 保持/复位解除），**159/159 全绿**。
- 注意 Lua 坑：极性判断勿写 `cond and a or b`（b 为 false 时结果落到 b）——用 `(x ~= 0) == FLAG`。

## 防提前置 2 定案：位置核对（2026-09-29 17:33）
- 50ms 防抖不够：内核 `idle` 语义 = "没在动"（READY/STOPPED 且 drive bit10），**中途去使能/超时停车时 idle=1 但离目标几百 mm**。实证：17:29:47 机器人急停信号 4x145=1 触发联锁 → 轴在 496.591mm 半路去使能 → 脚本按 idle 误报到位 2。

## 固件 502 客户端断开回收缺陷（2026-10-01，真机探测发现，已修待部署）
- 现象：PC 端反复快速连 502 后，新连接被 RST；`ss` 显示 6 条来自同一 PC 的 **CLOSE-WAIT**；触摸屏+机器人 2 条 ESTAB 合计 8 = 客户端上限 → 满槽拒新连；kine-x CPU 61%、sys 27%（poll 空转）。
- 根因：`modbus_server.cpp::poll_once` 收循环 `recv()==0`（对端 FIN）只 `break`，未置 `dead` → 槽位永不回收（keepalive 对半开连接也不生效，须应用层 close）。
- 修复：`n==0` 置 `dead`；硬错误（非 EAGAIN/EWOULDBLOCK/EINTR）同样置 `dead`。回归 `modbus_server_test` §6（8 连接全关→第 9 连可用；无修复 51/52，有修复 52/52）。
- 部署（2026-10-01 18:56）：18-push-src → 36-build-m2（板上编译约 2 分钟）→ 手动 `cp /opt/kine-x/app/kine-x /opt/kine-x/bin/` + `systemctl restart`（**勿用 finalize：它会先删产物再空等**）；重启清空被占槽位。
- 复验：连满 8 → 全关 → 第 9 连立即可用（修复前被 RST）；`ss` 无 CLOSE-WAIT；心跳 29→32 递增；触摸屏/机器人自动重连。
- 教训：探测/压测固件 502 时避免同一 IP 快速连打；此缺陷在触摸屏/机器人偶发重连场景会导致"再也连不上"。
