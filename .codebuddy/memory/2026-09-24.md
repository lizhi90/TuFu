## ★★真根因（v0.1.6 仍看不到）：CLI 装 VSIX 不会让**运行中**的编辑器重扫扩展清单

**决定性证据链**（都在 `~/.vscode-server/data/logs/20260923T162715/`）：
- `remoteagent.log`：**安装全部成功**（0.1.1→0.1.6 逐次 `Installing/Extracted/installed successfully`），
  时间 18:57→19:11，用的是 `productVersion 1.138.0`。
- `remoteexthost.log`（**真正加载扩展的进程**）：**全文搜不到任何 kine-x 记录**。
- 日志目录名 `20260923T162715` = **9月23日**启动的会话；18:00 后只有 remoteagent/其它扩展在写，
  **扩展宿主从未重启**。
- `extensions.json` 里 0.1.6 已正确注册（`pinned:true`, `source:"vsix"`）。

**结论**：`remote-cli/code --install-extension` 只是把文件落到磁盘 + 更新 `extensions.json`；
**正在运行的编辑器缓存了清单，不会重扫**。`Developer: Reload Window` 只重启**扩展宿主**、
**不重扫清单**，所以照样加载不到 → 用户重载多少次都没用（**不是用户操作问题，是我给的指引不对**）。

**唯一可靠解法**：**完全关闭编辑器/远程连接再重开**（`Remote: Close Remote Connection`
或彻底关掉整个 VS Code 窗口），让扩展宿主进程**重建并重扫清单**。

**已做的环境准备**：删除旧版本残留目录 0.1.1~0.1.5，只留 `kine-x.kinex-debug-0.1.6`（清单也只指向它）。

**教训（写给以后）**：
1. 用 CLI 给**运行中**的编辑器装扩展后，必须提示用户**完全重开**，不能说「Reload Window 即可」；
2. 排查扩展不显示时，**先看 `remoteexthost*.log` 有无该扩展的 activate 记录**——
   没有就是「压根没加载」，不要往 UI/贡献点方向猜（我此前连做三版 UI 方案都是白费）。
